フォルダの相対パス

PCのフォルダもパス指定があり、絶対パスや相対パスの概念があります（どちらから言うとこっちが先の話）

相対パスは、「今いる階層」と、「今いる階層から下のフォルダを指定する方法」と、「今いる階層から下のフォルダを指定する方法」の３つを理解しておけばいい


サンプルとして左記のフォルダ構造があったとして、ここでのパス移動やパス参照を例に説明します（C:.は、C:\TEMP\MyWeb\src）

  • パスのセパレータ

    Windowsでは、パスのセパレータは「\（バックスラッシュ）」を使っているのでパスを表示させると以下のようになっている

    
            > $pwd
            C:\TEMP\MyWeb\src     # パスのセパレータは「\（バックスラッシュ）」になっている

    しかし、Webの世界ではパスのセパレータは「/（スラッシュ）」を使うので、この点は違う （だけどパス指定の概念は同じ）

    • （おまけの話）

      おまけの話として、PowerShellはセパレータに「/」も「\」も使える

      
                C:\TEMP\MyWeb\src < ls pic\xx.png    # PowerShellだと、バックスラッシュでパス指定もできる
                C:\TEMP\MyWeb\src < ls pic/xx.png    # PowerShellだと、スラッシュでパス指定もできる

      Cmdは、バックスラッシュしか使えない

      
                rem Cmdは、バックスラッシュでのパス指定のみ可
                C:\TEMP\MyWeb\src < dir pic\xx.png
                rem Cmdは、スラッシュでのパス指定はエラーになる
                C:\TEMP\MyWeb\src < dir pic/xx.png

      Cmd.exeは、MS-DOSのCmd.comを継承しているので「/」はオプション指定に使っている。このため「/」をパス指定に使えないのでしょうね

  • 同じ階層（今いる所）とは

    あるフォルダにいる時、そこから見えるものは同じ階層にあるという。同じ階層にいるファイルやフォルダは、パス指定なしで直接指定できる 

    • 
                > ls
                Mode    LastWriteTime       Length  Name
                ----    -------------       ------  ----
                dar--   2000/03/01  15:18           css
                dar--   2000/03/01  15:18           lib
                dar--   2000/03/02   7:24           pages
                dar--   2000/03/01  15:20           pic
                dar--   2000/03/01  15:20           script
                dar--   2000/03/01  15:20           参考資料とか
                -a---   2000/02/28   6:07     3895  index.html
                -a---   2000/03/02   7:25       33  readMe.txt                
                # 今見えている以下のフォルダやファイルは同じ階層にいるもの

    • 同じ階層にあるフォルダの指定方法は以下の方法で可能

      • 「サブフォルダ名」から初めてパスを指定する
      • 「./」でカレントフォルダの下 を示してパスを指定する
      • 「/」で始めるとだめ。これはルートからのパスになるため 
      • 
                    > ls pages/manga/pic/1.png       #「サブフォルダ名」から初めてパスを指定する
                    Mode                 LastWriteTime         Length Name
                    ----                 -------------         ------ ----
                    -ar--          2000/07/12    18:34          19789 1.png

                    > ls ./pages/manga/pic/1.png     #「./」でカレントフォルダの下 を示してパスを指定する
                    Mode                 LastWriteTime         Length Name
                    ----                 -------------         ------ ----
                    -ar--          2000/07/12    18:34          19789 1.png

                    > ls /pages/manga/pic/1.png      #「/」で始めるとルートからのパスになる
                    Get-ChildItem: Cannot find path...  # ← ルートからのパスにはこのフォルダ無い。エラー
  • 親の階層に上がるには

    1つ上の階層は親の階層といったりする。この階層に上がるには「../」で指定する。さらに上は「../../」と指定する。つまり「../」が1つ上を示している。

    
            > cd ../       #1つ上に上がる
            > cd ../../    #2つ上に上がる

    例）今、manga/picフォルダにいるとして、そこからscriptフォルダ内を見る場合

    
            PS C:\TEMP\MyWeb\src\pages\manga\pic> ls ..\..\..\script\
            Mode                 LastWriteTime         Length Name
            ----                 -------------         ------ ----
            -ar--          2000/03/20    17:00            507 hoge.js
            -ar--          2000/03/16     2:32             80 fuga.js


    ① 今いる所は、manga/pic

    ② 1つ上は、manga階層

    ③ 2つ上は、pages階層

    ④ 3つ上は、ルート

    ⑤ その下にscriptフォルダがある

HTMLのパス指定

HTMLのパス指定

HTMLのパスの指定方法は、絶対パス、相対パス、ルート相対パスがあります

基本的な考え方は、フォルダのパス指定と同じです（パスのセパレータが違うなどの差はあるが概念は同じ）。なので、CUI になれている人はすぐイメージできると思います。GUIの人でも分かってしまえば難しくないです

  • 絶対パス

    絶対パスはフルパスの事。Webの場合は、「http://」や「https://」のプロトコルで始まりファイル名hoge.htmlまでの全部のパス。

    絶対パス指定は、自分のページ中でも使う事は可能だけど、自分のページ内のリンク等では相対パスやルート相対パスを使うのが一般的と思います。絶対パス指定は外部のページへのリンクなどで使うのが多いと思います（自分は外部ページのリンクにしか使ってない）。 

    
            <a href="https://hoge.com/pages/neko/pic/neko.jpg" target="_blank">neko</a>
  • 相対パス

    相対パスは、今のページからの相対位置を示すもの

    つまり、今コーディングしているhtmlページからの位置を指定する。なので、ある階層のページAから画像フォルダへのパスと、別の階層のページBから画像フォルダへのパスは異なる（当たり前）

    ページ数が多い構造で、相対パス指定を使っている場合、パスが変わると影響が大きい。（ルート相対パスを使う場合も同じような影響がありますが、ルート相対パスの場合はまだ影響が少ないです）

  • ルート相対パス

    サーバをルート（基準）とする相対パス指定。今いる所を基準とする相対パスよりも変化に強い

    ルート相対パスは、今のページを基準とした相対パスではなく、サーバルートを基準とした相対パスってこと
