Settings.json

Settings.jsonは、VSCodeの設定内容が書かれている設定ファイルです。なのでGUIの「設定」 から行うよりこのファイルを直接編集した方がはやい

まずはjsonって何から

jsonは「JavaScript Object Notation」の略で、設定を記述したりソフトウェア間でデータ交換したりするため構造化されたデータ形式のこと。名前の通りJavaScriptが起源でJavaScriptで使っている書き方を使っています。しかしJavaScriptだけではなくいろいろな言語でサポートされています（つまりそれだけ使いやすいし優れたフォーマットってことなんやろう）

  1. キー：バリューのペアで記述する

    "キー": バリュー, のペアで記述します。キーは必ずダブルクォーテーションで囲みます。キーとバリューは「:（コロン）」で区切り、このペアセットが複数ある場合は「,（カンマ）」で区切ります

  2. 軽量、シンプル

    テキスト形式で記述されるデータで、軽くてシンプルな構造

  3. 人間にも機会にもやさしい

    シンプルな構造のため人が見ても大体わかる（xmlだとぱっとわからん）、ソフトウェアが見てもパースしやすい

  4. コメント不可

    基本的にコメント文は使えません（データだから当たり前か）

  5. サンプル例

    
                {
                  "name": "HouNeko",                    // Stringデータ
                  "age": 100,                           // Numberデータ
                  "isHuman": false,                     // Booleanデータ
                  "favorite": ["Programming", "Neko"],  // Arrayデータ（配列も使える）
                  {                                     // Objectデータ（Json内にjsonも可能）
                    "phone": "secret",
                    "address": "secret"
                  }
                }

自分の感覚では、XMLより簡単でCSVより自由度や表現力が高いって感じです（CSVは一番原始的な構造で軽いがデータの追加や削除に激弱）

Settings.jsonの開き方

  1. コマンドパレット（Ctrl+Shift+P）を起動する
  2. 「open user settings」と入力して、Settings.jsonを検索して、開く

Settings.jsonはどこにあるの？

Settings.jsonは、%AppData%\Code\User\Settings.json にあります

※上記はVSCode全体のSettings.jsonファイル。フォルダ毎に.vscodeフォルダがありその中にもSettings.jsonがあります。名前は同じですが別々の設定です。.vscode内のSettings.jsonはそのプロジェクト固有の設定、ユーザプロファイルにあるSettings.jsonはVSCode全体の設定です 


    PS> Get-ChildItem $env:AppData\Code\User
    Mode           LastWriteTime         Length Name
    ----           -------------         ------ ----
    ...            ...                   ...    ...
    ...            ...                   ...    ...
    -a---          yyyy/mm/dd hh:mm      xxxxx  settings.json   # ← これ

Settings.jsonのコメントのわな

Settings.jsonの設定は自分には分かりにくく、設定値の意味などをコメントを書いていました。この時、Jsonはコメントが無いデータ構造なので、VSCodeのsettings.jsonは特別なのかなとは思ったことがあったのですが、現状コメントが書けていたのでそれ以上は気にしていませんでした。

この運用だと、例えばコマンドパレットで設定を変更して保存しようとする時に失敗してしまうことが起きることがあります。settings.jsonを見てもエラーや警告等は出ていないので気づきにくいですが、このコメントが悪影響を与えている可能性があります。

どういうことかというと、settings.jsonは人間見えには「JSONIC」で書かれていて、内部でjsonファイルになっています（だからコメントが書ける） つまり、コマンドパレットで設定を変更して保存する時に、JSONICがjsonで保存されます。この時、変なところにコメント文があると、jsonへの変換が失敗して保存できないという現象になります。 


            ...
    "window.activeBorder": "#fc11c1", // アクティブウィンドウ枠線の色   ← 行末にコメントがあると失敗する可能性がある
    "window.inactiveBorder": "#9dee9d", // 非アクティブウィンドウの枠線の色   ← 〃
            ...
    "editor.fontsize": 14
    //Tabサイズ             ← 設定の途中でコメントがあると失敗する可能性がある
    "editor.tabsize": 2
            ...

このため、settings.json（JSONIC）にコメントを書く場合は、複数行にまたがるようなコメントブロックはファイルの先頭にまとめて、途中のコメントはそのブロックの前に1行程度で書くようにする。または、settings.jsonにはコメントを一切入れずに、別のテキストファイルを用意して、そのsettings.json内容を書いておくような運用にする（この場合、2つのファイルを管理するので整合性がずれてしまう可能性があるので、settings.jsonの先頭にコメントを集約する書き方の方がいいと思う）
