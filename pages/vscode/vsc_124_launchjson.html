Launch.jsonとは

launch.jsonは、VSCodeでデバッグする時の動作を定義する設定ファイルです。F5キーでRunする時に参照されます

launch.jsonは、ワークスペースのルート直下にある「.vscode」フォルダ内に作成されます

  • 作成手順
    1. VSCodeのサイドバーで実行とデバッグをクリック（or Ctrl+Shift+D）
    2. launch.jsonファイルを作成をクリック
    3. デバッグ環境を指定（C++、Node.js、Python、…）

Launch.jsonの設定例

configurations（複数形）がデバッグ設定のキー。キーの値は配列になっていて各配列要素が各言語の設定になっています。以下の例は、PowerShellとCのデバッグ設定です

この例は1つのlaunch.json内で複数言語のデバッグ設定を定義していますが、開発言語がいっぱい増えてくるとlaunch.jsonも言語毎に分けた方がいいかもしれません（PowerShell開発フォルダ、C言語開発フォルダ、・・の下にそれぞれ用の.vscodeフォルダ を作成してそれぞれ用のlaunch.jsonを定義したほうがいい）


          {
            "version": "0.2.0",
            "configurations": [
              {
                /* こっちがPowerShellのデバッグ設定 */
                "name": "PowerShell: Launch Current File",
                "type": "PowerShell",
                "request": "launch",
                "script": "${file}",
                "args": []
              },
              {
                /* こっちがCのデバッグ設定 */
                "name": "C Debug (gcc)",
                "type": "cppdbg",
                "request": "launch",
                "program": "${fileDirname}\\${fileBasenameNoExtension}.exe",
                "cwd": "${fileDirname}",
                "MIMode": "gdb",
                "miDebuggerPath": "C:/Program Files/mingw64/bin/gdb.exe",
                "externalConsole": false,
                "preLaunchTask": "build c"
              }
            ]
          }
launch.jsonの各設定キーと意味
キー名 意味
name デバッガラベル名（わかりやすい名前でいい）。F5を押下した時に表示される名前
type デバッグアダプタ名
request launchは、新しくデバッグ開始
program 実行モジュール名（exeファイル名とか）
cwd 実行時のカレントディレクトリ
MIMode デバッガモード
miDebuggerPath デバッガ本体へのフルパス
externalConsole tureなら外部コンソール、falseならVSCodeのターミナル
preLaunchTask tasks.jsonで定義している実行名（ラベル）。これを定義していた場合、tasks.jsonのlabelで指定しているタスクが実行される

type、MIModeの違い

まず、「miDebuggerPath」キーは分かる。これはまさにデバッガ本体のフルパスを指定している。

最初分からなかったのは、「type」キーと「MIMode」キーの違いです。

いろいろ調べてみると、VSCodeのデバッグは階層構造になっていて、デバッガ本体のフルパスを指定したらいいというものではないという事です（これは、VSCodeが特定の言語のエディタではなく、IDEのようデバッグ機能も持たないからだと思います。これらは拡張機能と設定で賄うようにして自由度がある設計になっているのだと思います）

typeキー

typeが指定するのは、デバッグアダプタの種類です。デバッグアダプタは拡張機能としてVSCodeに組み込まれます（C言語の場合、C/C++ Extension拡張機能をインストールするとcppdbg、cppvsdbgが使えるようになる）。デバッグアダプタは、VSCode上のユーザデバッグ指示を、MIModeで指定されたプロトコルに変換してデバッガに渡すという役割を行っています

typeは、デバッグ時にVSCodeが誰と話をするかを指定しているということです

MIModeキー

デバッグの方式・プロトコルはいくつかあり、どれにするかを指定します。例えばGNU方式だとgdb、LLVM方式だとlldbがあります。これもデバッガ本体ではなくデバッグアダプタにどのプロトコルでデバッグ指示を翻訳（MI：Machine IF。SW間でデバッグ指示をやり取りする）するかを指定する


        イメージ例
        ユーザがF10でステップ実行
          ↓
        VSCodeがデバッグアダプタに以下のような指示を渡す
              {
                "command": "next"
              }
          ↓
        デバッグアダプタはMIモードのプロトコルで変換
              -exec-next（これがMI：MachineIF。人間のデバッグとは違う）
          ↓
        デバッガ本体がデバッグ指示を実行
