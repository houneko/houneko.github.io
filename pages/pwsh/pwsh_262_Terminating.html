終了するエラーと終了しないエラー

終了するエラー

PowerShellのエラーは、終了するエラーと終了しないエラーというものに分かれる。このエラーは名前の通りスクリプト実行を停止するようなエラーと、そのエラーが発生してもスクリプト実行は停止しないエラーという振る舞いになる。

また、終了しないエラーも例外に昇格させることができるので、PowerShellのエラーハンドリングを最初に学ぶ時にすこしややこしい印象を与えてしまう

終了するエラー

終了するエラー「Terminating Error」は、その名の通りスクリプト実行を停止させるようなエラーのこと

  • このエラーは例外
  • try～catchで捕まえることができる
  • throwでこのエラー（例外）を発生させることができる
  • $Errorにエラー情報は格納される

throwで終了するエラーを発生させる

throwで例外を発生させることができる。例外は終了するエラーなので、tryブロックで発生させた例外はcatchブロックで捕まえることができる


        try {
          throw "user throw"    #throwを実行して例外を発生させる
          return "AB"
        }
        catch {
          Write-Host "例外： $($_.Exception.GetType().FullName)"
        }

        #実行結果
        例外： System.Management.Automation.RuntimeException    #catchブロックに入ってる
        AB

※throwは、tryブロック以外で書くと誰もcatchしないので即終了する（最終的にPowerShellが例外を受け取りエラー表示する）

throwを返す関数

関数コール元はtryブロックから関数をコールする。関数は内部の処理でエラーがあればthrowを投げる

この実装は、エラーフラグを返しコール元でそれを判断するという処理と同じようなものだけど、throwを使う方がコードがシンプルになる


        #////////////////////////////////////////////
        # throwを投げる関数
        function DoMyHoge {
          param ($file)

          if (-not (Test-Path $file)) {
            # エラーの場合、throwを投げる
            throw 'ファイルがありません'
          }
        }

        #////////////////////////////////////////////
        # Main
        Write-Host "start"
        try {
          # throwを投げる関数をコール。neko.txtは存在しないファイル
          DoMyHoge "neko.txt"
        }
        catch {
          Write-Host "DoMyHoge()が失敗しました"
        }

        # 実行結果
        start
        DoMyHoge()が失敗しました

終了しないエラー

終了しないエラー

終了しないエラー「Non-Terminating Error」は、その名の通りでこのエラーが発生しても停止しない

  • このエラーは例外だけど例外として扱われていない（内部的には.NETの例外は発生しているが、PowerShellがthrowしないようにしている）
  • try～catchで捕まえることができない（例外じゃないから。throwされていないから）
  • $Errorにエラー情報は格納される

終了しないエラーが終了しないことの確認

以下のサンプルを実行すると、tryブロック内のGet-Contentは指定されたファイルが存在しないので失敗する。しかし、ファイルが存在しないエラーは「終了しないエラー」となるので、エラー表示はでるけどスクリプトは終了しない。

スクリプトが終了しないのでエラー以降のWrite-Hostは表示されている。また、例外じゃないのでcatchブロックのWrite-Hostは表示されていない


        try {
          # 例外が発生する処理
          Get-Content "throw.txt"                                   # 例外（もどき）が発生するがthrowされない
        }                                                           # 処理は停止しない
        catch {
          Write-Host "例外： $($_.Exception.GetType().FullName)"    # ここには入らない
          return "AB"
        }
        finally {
          Write-Host "this is finally block."                       # finallyブロックは例外有無によらず入る
          My-CloseHoge
          My-ResetHoge
        }
        Write-Host ("end test")                                     # try～catch～finallyブロックの外

        # 実行結果
        # Line |
        #   28 |    Get-Content "throw.txt"                         # エラー表示はされる
        #      |    ~~~~~~~~~~~~~~~~~~~~~~~                         # （このエラー情報が$Error変数に格納されている）
        #      | Cannot find path 'xx\throw.txt' because it does not exist.
        # this is finally block.                                    # finallyブロックでの表示
        # end test                                                  # ブロックが終わった後の表示

どのようなエラーが終了しないエラーなのか

終了しないエラーはたくさんあります。以下はサンプル例

  • ファイルやパス系のコマンド

    以下のファイルやパスを扱うコマンドレットなどは終了しないエラーになる。ファイル・パス対象が存在しなかった、処理できなかった等。でも処理全体を止めるほどではないか。という扱いっぽい

    • Get-Content
    • Get-Item
    • Remove-Item
    • Copy-Item
  • 権限やアクセス系のコマンド

    権限が足らないやアクセス権を持ってない操作などは終了しないエラーになる。権限が足らずアクセスできなかった等、でも処理全体を止めるほどではないか。という扱いっぽい

    • Get-Content
    • Remove-Item
  • WMI/CMI/ネットワーク系のコマンド

    指定したサービスやプロセスが見つからない系のエラーは終了しないエラーになる。見つからなかったけど処理全体を止めるほどではないか。という扱いっぽい

    • Get-Service
    • Get-Process

終了しないエラーを終了するエラーに変える

終了しないエラーが起きた場合、エラー表示してそのまま処理が継続されるが、エラーで終了させたいケースも存在する。このため終了しないエラーを終了するエラーに昇格させることもできるようになっています

  • $ErrorActionPreference = 'Stop'

    $ErrorActionPreference変数はPowerShellの環境設定変数でスクリプト全体に対するエラーの挙動を指定するもの

    この変数にStopを代入すると、スクリプト全体でエラーがあったら例外扱いとなり処理を停止するようになる。この変数にstopを代入する前の値を保存しておきfinallyブロックで元に戻す

    以下の例は、存在しないファイルをGet-Contentしている。通常はこのエラーは終了しないエラーなので、catchブロックに入らずそのまま処理が進むが、$ErrorActionPreference = 'Stop' が指定されているので、例外がthrowされてcatchブロックに入っていることがわかる

    
            # スクリプト全体でエラーがあれば停止するように設定する
            $oldEAP = $ErrorActionPreference
            $ErrorActionPreference = 'Stop'
            try {
              # 以下の処理は「終了しないエラー」になるので、throwされない
              # なので、catchブロックに入らずそのまま処理が進む
              Get-Content "throw.txt"
            }
            catch {
              Write-Host "例外： $($_.Exception.GetType().FullName)"
            }
            finally {
                $ErrorActionPreference = $oldEAP    #元の設定値に戻しておく
            }

            #実行結果
            例外： System.Management.Automation.ItemNotFoundException    #catchブロックに入ってる
  • -ErrorAction Stop

    各コマンドレットに-ErrorActionオプションをつけて、個別にエラー時の振る舞いを定義できる。このオプション値を stop に設定すると、エラーがあった場合停止するようになる（例外に昇格）

    
            try {
              # 以下の処理は「終了しないエラー」だが -ErrorAction Stopが指定されているので例外に昇格する
              # throwされるのでcatchブロックに入る
              Get-Content "throw.txt" -ErrorAction Stop
            }
            catch {
              Write-Host "例外： $($_.Exception.GetType().FullName)"
            }

            #実行結果
            例外： System.Management.Automation.ItemNotFoundException    #catchブロックに入ってる

    ちなみにスクリプトに$ErrorActionPreference='Stop'が指定されている場合、-ErrorActionを設定するとどうなるか？この場合、-ErrorActionの設定の方が優位なので、-ErrorActionの設定が優先される
