CmdletBinding属性

CmdletBinding属性とは

CmdletBinding属性は、自分の関数やスクリプトを「高度な関数」または「高度なスクリプト関数」にするための属性です。
何かよくわからんが、PowerShellのコマンドレットが持つパラメータ（-WhatIfや、-Debug、-ErrorAction、-Verbose、・・・）を自動的にサポートしてくるようにする属性と理解していたら大体あっていると思う。コマンドレットが持つ基本的な機能を継承するってことなのでバインディングなのかな。

CmdletBinding属性を指定するだけでいいが、以下の注意点がある

  • 関数またはスクリプトの一番先頭に書かないといけない
  • [CmdletBinding()]の次の行には、Param()が必要
  • 角かっこで、CmdletBinding() を囲む（[]が属性だから）つまり、[CmdletBinding()] と書く

    []で囲まないと、CmdletBinding() と解釈されてしまう。

今までは、例えば -Debugを使いたい場合、自分でParam()に[Switch]型で$Debugを定義して使っていたけど、[CmdletBinding()]属性を付ければ、Param()で定義、$Debug変数が定義されていたらどうこうというIf文も書かなくていい。 


        #//////////////////////////////////////////////////////////////////////////
        # 今までやっていた方法（自分で、$Debugを定義するやりかた）
        #
        Param(
          [Switch]$Debug      #// ← ** [CmdletBinding()]属性をつけたら、この定義は要らない **
        )

        #// ↓ ** [CmdletBinding()]属性をつけたら、このif文は要らない **
        if($Debug) {$DebugPreference = "Continue"} else {$DebugPreference = "SilentlyContinue"}
        ...
        Write-Debug ("Enter $func_name")
      

        #//////////////////////////////////////////////////////////////////////////
        # [CmdletBinding()]属性を指定するやりかた
        #
        [CmdletBinding()]   # これがCmdletBinding()の属性指定
        Param()
        ...
        Write-Debug ("Enter $func_name")  #何も宣言せずに、すぐWrite-Debugが使える

        CmdletBinding()を先頭に定義しておけば、実行時に以下のようにするだけでいい。これで、Write-Debugのコードが出力される
        PS> .\Hoge.ps1 -Debug

VSCodeのインテリセンスではCmdletBindingじゃないけど・・・

VSCodeを使っているとインテリセンスが効いて、CmdletBi・・と入力すると、候補にCmdletBindingAttributeが出てくる。これは、dotnet型が本当の型なので、CmdletBindingAttributeが本当の型だから。でも、PowerShellではそれのAliasとして「CmdletBinding」を使っているので、気にせず「CmdletBindingAttribute」を選択すればいい。これを選択してもPowerShellのps1ファイルの場合は「CmdletBinding」として入力される。

CmdletBindingは全部の関数につけないとだめ？

結論から言うとその関数を単独で使う予定があるかどうかだと思います。あるps1ファイルの中にある関数を単独で実行したい場合はつけた方がいいけど、ps1ファイル内で使うだけなら各関数には[CmdletBinding()]を書かなくてもいい

以下の例は、Test-Hoge.ps1 ファイルで、この関数は以下のように作っている

  • Test-Hoge.ps1ファイルの中には、内部関数「hoge1()」がある
  • Test-Hoge.ps1ファイルの先頭で、[CmdletBinding()]属性を指定している
  • 内部関数「hoge1()_」には、[CmdletBinding()]属性は指定していない

        #//
        #// Test-Hoge.ps1ファイル
        #//
        [CmdletBinding()]                       #// Test-Hoge.ps1ファイルの先頭で
        param()                                 #//  [CmdletBinding()]属性を指定している
                                                #//  ∴このスクリプトは高度化している
        Write-Verbose("Verbose表示 01")
        Write-Debug("start TEST Code")

        #// 内部関数 Hoge1()
        function Hoge1 {                        #// 内部関数Hoge1()は、[CmdletBinding()]属性はなし
          write-Host("Write-Host: Hoge1")       #// これは、Write-Hostなので必ず表示される
          Write-Debug("Enter Hoge1")
          Write-Verbose("this meg from Hoge1")
          Write-Debug("Exit Hoge2")
        }

        #// main
        Write-Debug("now call Hoge1()")
        Hoge1                                   #// 内部関数Hoge1() をコール

        Write-Verbose("Verbose表示 02")
        Write-Debug("end TEST Code")

実行テストと結果

  • 実行結果１

    実行結果１では、コマンドラインからps1ファイルを実行したもの。この時のコマンドライン引数は「-Verbose」と「-Debug」。
    Test-Hoge.ps1は、高度化しているのでこれらの引数を受け取ることができる

    この結果を見たらわかるが、内部関数Hoge1()は[CmdletBinding()]属性をつけていないが、Write-VerboseやWrite-Debugは表示されている。これはスクリプトファイルの先頭で指定した[CmdletBinding()]属性により、Preference変数が設定されるので、内部関数にもこの設定値に従った動作となっているから。

    なのでps1ファイル内でつかう関数には[CmdletBinding()]属性は指定しなくてもいいということになる

    
            PS > .\Test-Hoge.ps1 -Debug -Verbose   # ← コマンドライン引数は「-Verbose」と「-Debug」でスクリプトを実行
            VERBOSE: Verbose表示 01
            DEBUG: start TEST Code
            DEBUG: now call Hoge1()
            Write-Host: Hoge1                         
            DEBUG: Enter Hoge1                        # 内部関数Hoge1()は[CmdletBinding()]属性を指定していないが
            VERBOSE: this meg from Hoge1              # Write-Verbose や Write-Debug が表示されていることがわかる
            DEBUG: Exit Hoge2
            VERBOSE: Verbose表示 02
            DEBUG: end TEST Code

  • 上記の結果の通り、ps1ファイル内から内部関数を使う場合は内部関数に[CmdletBinding()]属性をつけなくてもいいことが分かりましたが、この関数を単独で使う場合は話が違います。以下の例は、ドットソースで実行して関数をロードし、関数だけをコールしてみた結果です。

    実行結果２

    この結果では、関数内部にあるWrite-DebugやWrite-Verboseは出力されていないことが分かります。ps1ファイルでは[CmdletBinding()]属性をつけているけど、この内部関数には[CmdletBinding()]属性が無いので、-Debugや-Verboseが効かないということです 

    
            PS > . .\Test-Hoge.ps1       #// ドットソースでps1ファイルを実行し、内部関数をロード
            PS > Hoge1 -Debug -Verbose   #// -Debug や -Verbose をつけて関数を実行してみる

            結果）
            Write-Host: Hoge1   #// Hoge1()関数内の Write-Host だけが出力されている

  • とりあえず、ps1スクリプトで動作させる分には内部関数にも属性がかかるのでいいけど、関数を個別に使いたくなった場合は各関数内でも[CmdletBinding()]属性を指定してあげる必要がある

    次にこの内部関数に[CmdletBinding()]属性をつけてどうなるかを試してみる

    
            #//
            #// Test-Hoge.ps1ファイル
            #//
            [CmdletBinding()]                       
            param()                                 
                                                    
            Write-Verbose("Verbose表示 01")
            Write-Debug("start TEST Code")

            #// 内部関数 Hoge1()
            function Hoge1 {
              [CmdletBinding()]                     #// 内部関数Hoge1()にも [CmdletBinding()]属性をつける
              param()                               #// param() も必要。変更点はこれだけ
              write-Host("Write-Host: Hoge1")       
              Write-Debug("Enter Hoge1")
              Write-Verbose("this meg from Hoge1")
              Write-Debug("Exit Hoge2")
            }

            #// main
            Write-Debug("now call Hoge1()")
            Hoge1                                   

            Write-Verbose("Verbose表示 02")
            Write-Debug("end TEST Code")
    実行結果３

    以下の結果は、関数Hoge1()に[CmdletBinding()]属性をつけて、もう一度関数をロード。Hoge1() を -Debugや-Verbose 引数をつけて実行してみたものです

    
            PS > . .\Test-Hoge.ps1       #// ドットソースでps1ファイルを実行し内部関数をロード
            PS > Hoge1 -Debug -Verbose   #// -Debug や -Verbose をつけて関数を実行してみる

            結果）
            Write-Host: Hoge1
            DEBUG: Enter Hoge1              #// Write-Debug結果が出力されている
            VERBOSE: this meg from Hoge1    #// Write-Verboseも出力されている
            DEBUG: Exit Hoge2
