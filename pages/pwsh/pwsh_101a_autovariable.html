PowerShellの自動変数

自動変数は、PowerShellが自分で作り各情報を設定している変数。自動変数はユーザが変更したりすることをはできない （書き換えた場合動作は保証されない）

自動変数はいっぱいあります（7.xでは、42種類位ある）。
詳しくはMicrosoftのページ「about_Automatic_Variables」で

自分が良く使う自動変数

  • $PSVersionTable

    この自動変数は、PowerShellのバージョンを格納している

    
            $PSVersionTable   # ← $PSVersionTable自動変数を表示させてみる。以下の結果はPowerShell Coreでのもの
              Name                           Value
              ----                           -----
              PSVersion                      7.5.4
              PSEdition                      Core
              GitCommitId                    7.5.4
              OS                             Microsoft Windows 10.0.26100
              Platform                       Win32NT
              PSCompatibleVersions           {1.0, 2.0, 3.0, 4.0…}
              PSRemotingProtocolVersion      2.3
              SerializationVersion           1.1.0.1
              WSManStackVersion              3.0
  • $PSScriptRoot

    今実行したスクリプトのパスが代入される自動変数。以下のデバッグ画面を見ると左ペインの変数一覧に$PSScriptRootが表示されていることがわかる。この変数にはこのスクリプトを実行した時のパスが入っている

    スクリプト内からは見えるが、ターミナルからは空文字に見えるので注意

  • $PSBoundParameters

    この変数は、コマンドライン引数の名前と値を「キーとバリュー」で辞書のような形で格納しています。モジュールのデバッグで「-Debug」オプションをモジュール関数に渡す時に使えると思います

    
              #//
              #// TEST Program
              #//
              [Cmdletbinding()]
              param(
                [Int]$intNumber,
                [Switch]$swHoge,
                [String]$stName
              )
              Write-Debug ('$PSBoundParameters = ' + ($PSBoundParameters | Out-String))
              
              #//実行
              > .\myTest2.ps1 -intNumber 10 -swHoge -stName Neko -Debug

              #//結果
              DEBUG: $PSBoundParameters =
              Key       Value
              ---       -----
              intNumber    10       #// ←各引数名と値が、KeyとValueに格納されている
              swHoge     True
              stName     Neko
              Debug      True
  • $_（見にくいけど$の後に「＿」アンダーバーがついてる）

    一番良く使うかも。「$_」は、パイプライン処理で使うための自動変数。 これは、今パイプで渡された１つのオブジェクト を意味している

    横道にそれるが、パイプラインの動作は前段の結果（オブジェクト）が一気に渡されるのでは無い！なので、前段のコマンドレットの結果の1つがパイプを通って次のコマンドレットに渡される。この時の後段のコマンドレットはそれを「$_」で受け取っている 

    
            Get-Process | ForEach-Object {$_.Name}  # ← Get-Processの結果（オブジェクト）が丸ごと一気にパイプで渡されるのでは無い！
                                                    # ← Get-Processでプロセス全体のオブジェクトができたら、それを1つずつ（1個のプロセス）
            結果）                                  # ← パイプで渡すなので、ForEach-Objectの「$_」には 1プロセスずつ渡されてくる
            ・・・
            Cmd
            ・・・
            Code
            Code
            ・・・

    また、もう1つの注意点で「$_」は、 スクリプトブロック「つまり{}」内でのみ使える。 という事も忘れないようしないと間違った処理を書いて悩んでしまうので注意

    
            Get-Command | Write-Host ($_.Name)  # ← エラーになる
                                                # ← なんでかというと「$_」はスクリプトブロック｛｝でしか使えないから

    パイプで渡すのは1オブジェクトずつだが、後段のコマンドレットによってはそれを全部受け取ってから処理するものもある

    
            Get-Process | ForEach-Object { $_.Name } | Sort-Object
            # この動作は、① Get-Processでプロセス一覧のオブジェクトができる（多分プロセス一覧の配列）
            # 次に ② として、①の結果を1つずつ ForEach-Objectに渡す。ForEach-Objectでは「$_」で受け取り名前を表示する
            # 次に ③ として、ForEach-Object「$_」オブジェクトを 次の Sort-Object に渡す
            # Sort-Objectでは、1つの「$_」を処理せずに全部渡されるまで待ち、最後にソートする
  • $$

    Microsoftのページ「about_Automatic_Variables」では「セッションによって受信された最後の行の最後のトークンを格納します。」という何かよくわからない説明だけど、要はこのセッションで最後に入力したもの が格納されている変数です

    
            > nekodesuka   # ← プロンプトにnekodesuka というわけ分からんものを流してみる（当然エラーになる ↓）
            nekodesuka: The term 'nekodesuka' is not recognized as a name of a cmdlet, function, script file, or ...
            Check the spelling of the name, or if a path was included, verify that the path is correct and try again. 

            > $$     # セッションの最後のトークンを表示させてみる
            nekodesuka  # 最後に実行したトークンが表示されている
  • $IsWindows

    現在のセッションがWindowsで行われているかを調べる時の自動変数。Windowsで実行している場合、$true が格納されている

    
            $IsWindows    # $IsLinuxや、$IsMacOS という自動変数もある
            結果）
            True
