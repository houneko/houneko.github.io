PowerShellでExcelを操作する

PowerShellでExcelを操作できます

ExcelはCOMモデルで作られているので外部から部品として操作することができます。PowerShellでExcelを操作する場合「New-Object」コマンドレットで、-ComObjectとして「Excel.Application」を指定することでExcelアプリケーションを操作できるようになります

※COM = Component Object Model。COMは、SWをコンポーネント（独立した処理を行う構成要素。独立したソフトウェアって感じかな）で構成する概念や仕様の事。なので外部からExcelを部品のように操作することができます

以下の操作を見ながら、PowerShellでExcelを操作する例を示します

比較用に、現在手動で「Book1.xlsx」と「Book2.xlsx」を開いた状態から始めます。1つのEXCELプロセスに、ブックオブジェクトが2つあるというイメージです（各Book1.xlsx、Book2.xlsxはスレッドではない）。

なので、新しくBook3.xlsxを起動すると、EXCELプロセス内に、Book1.xlsx、Book2.xlsx、Book3.xlsxが見え、Book3.xlsxを閉じると Book1.xlsx、Book2.xlsxだけになります

手動でBook1.xlsxとBook2.xlsxを起動した状態でのタスクマネージャー画面。
Excelプロセスが1つあり、その中にBook1.xlsxとBook2.xlsxオブジェクトが見えている。Book1.xlsxとBook2.xlsxはスレッドではなく、WorkBookオブジェクト

Get-Process -Name Excelの結果。プロセスID 32580 のExcelが手動で起動したEXCEL

Excelオブジェクトを生成する

まず最初にするのがこの操作です。New-Objectコマンドレットで、-ComObject として Excel.Application を指定して、Excelアプリケーションを生成します


        > $myExcel = New-Object -ComObject Excel.Application

Excel.Applicationを生成した後のタスクマネージャー画面とGet-Process画面での確認結果

Excelインスタンは生成されているけど、バックグラウンドプロセスになっており人間には見えない状態で起動していることがわかります（Visibleを$trueにしたら見える）

  1. タスクマネージャーで見た画面

    Excelオブジェクトを生成した直後は、画面には見えておらず、バックグラウンドプロセスとして生成されている

  2. Get-Processコマンドレットで見た画面

    New-Objectで作成したExcelは別プロセスID 28344として起動されている（手動でExcelブックを開くと既存プロセス内にブックオブジェクトが追加される）

生成しただけではExcelオブジェクトは見えない

New-Objectで生成したExcelオブジェクトは最初は見えないようになっている（バックグラウンドプロセスになっている）。この状態でも操作自体はできますが、一旦見える化しておきます

見える化は、$myExcelオブジェクトの「.Visible」プロパティの値を「$true」にすればいいです（もう一度見えなくしたい場合は、$falseを設定）


        > $myExcel.Visible = $true

$myExcelを見える化したもの。ブックオブジェクトやシートオブジェクトもまだ無い

また、見える化したらタスクマネージャーの表示がバックグラウンドプロセスからアプリプロセスに見え方が変わる（.Visibleを$falseにすると、バックグラウンドプロセスに戻る）

$myExcelオブジェクトを見える化すると、タスクマネージャーのアプリプロセスに別プロセスとして見えてくる

Excelオブジェクトの表示プロパティ

.Visibleプロパティの他にも表示関係のプロパティがあります。以下のプロパティはVBAでもほぼ同じ名前であり、VBAを使っていた人はどういうものかイメージできるかと思います

  • $myExcel.DisplayAlerts = $false
  • $myExcel.ScreenUpdating = $false
  • $myExcel.EnableEvents = $false
