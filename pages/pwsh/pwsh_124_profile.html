PowerShellの実行する前に必要な知識（profile.ps1）

プロファイル「profile.ps1」の基本概念

Profile.ps1とは

Profile.ps1ファイルは、拡張子がps1なのでPowerShellのスクリプトであるのはわかるが、これは何なのか？
PowerShellで言うプロファイルとは「Profile.ps1ファイル」の事でPowerShellが起動する時に実行される特別なスクリプトファイルのこと。しかし、最初はこのファイルは存在しないです。ということは、自分で作って自分がしたいことをこの中に書いておけば、PowerShellを起動する時に自動的にその処理を実行してくれるってことです

実行ポリシー

Profile.ps1ファイルもPowerShellのスクリプトなので実行ポリシーが実行可能となっていないといけない（RemoteSigned）。初期値では、Profile.ps1ファイル自体が存在しないので起動もかからず問題は起きない。しかし、Profile.ps1ファイルを作ると起動時に実行しようとするので、実行ポリシーが無いとエラーになる

$Profile自動変数

$Profileは「Profile.ps1ファイル」のパスを格納している自動変数です。この自動変数を見れば、Profile.ps1ファイルが存在しているかを調べることができます

プロファイルの作成（Profile.ps1ファイルの作成）

  1. プロファイル「Profile.ps1ファイル」のパスを調べる

    $Profile自動変数を表示させれば、プロファイル「Profile.ps1ファイル」のパスが表示される

    
            # $Profile を表示させるとプロファイル「Profile.ps1ファイル」のパスが表示される
            PS> $Profile
            C:\Users\xxx\OneDrive\ドキュメント\PowerShell\Microsoft.PowerShell_profile.ps1
  2. プロファイル「Profile.ps1ファイル」が作成済かを調べる

    Test-Pathコマンドレットでファイルの存在を確認することができる。Trueが返ってきた場合、プロファイルは存在する

    
            # Test-Path $Profile でプロファイル「Profile.ps1ファイル」が存在するか確認できる
            PS> Test-Path $Profile
            True
  3. プロファイル「Profile.ps1ファイル」を作成する

    Test-Path $Profileでfalseが返ってきた場合、プロファイルは存在しないので、New-Itemコマンドレットでファイルを作成する

    
            # プロファイル「Profile.ps1ファイル」を作成する
            PS> New-Item -Path $Profile -ItemType File -Force

プロファイル「Profile.ps1ファイル」に何を書けばいいのか？

決まっているわけではないので、何を書くかはその人依存。でも「プロファイルが読み込まれたよ」というメッセージだけ作ってもあんまり意味がない。自分は、いろいろな自作関数や自作ps1ファイルをPowerShellが起動時に使えるように設定 している。

Profile.ps1の真の役目

自分が思うプロファイル「Profile.ps1」の真の目的は、自作の*.ps1スクリプトや関数をバッチファイルのように使えるようにするためのものと思います。少なくとも自分の環境ではこの使い方がメインです。

自作関数、自作ps1ファイルと「Profile.ps1」

Profile.ps1を使わない場合

以下のような構造があり「Profile.ps1」は無いかまたは中身が空であるとして、自作関数や自作ps1ファイルを呼び出す場合を考えてみる。つまり、プロファイルを使わずに自作関数やps1スクリプトを実行する時のめんどくささを体感してみる。

  • 自作関数を実行するには

    この例では、自作関数はmyFunctionsフォルダに格納されている


    このファイルには関数定義のみ書いてある。関数名を指定することで関数がコールされる

    例えば、myfunc_hoge.ps1内にあるhoge()関数を実行するには、C:\My\MyCmd\myFunctionsフォルダまで移動するか、myfunc_hoge.ps1をフルパス指定してドットソースで実行する。これで関数名で呼び出すことができるようになる。

    C:\My\MyCmd\myFunctions> . myfunc_hoge.ps1

    一見問題無いように見えるが、自作関数が多くなると1つずつ同じことをしないといけないというめんどくささが存在する

  • 自作ps1スクリプトを実行するには

    この例では、自作ps1スクリプトはmyScriptFilesフォルダに格納されている


    このファイルには関数定義と関数コールが書いてあるので、スクリプト実行すれば内部の関数もコールされる

    例えば、Do-Hoge.ps1を実行するには、C:\My\MyCmd\myScriptFilesフォルダまで移動するか、Do-Hoge.ps1をフルパス指定して実行する。これでスクリプト名で呼び出すことができるようになる。

    C:\My\MyCmd\myScriptFiles> .\Do-Hoge.ps1

    これも同じで、一見問題無いように見えるが、ps1ファイルが多くなると1つずつ同じことをしないといけないのでめんどくさい

Profile.ps1を使う場合

Profile.ps1ファイルを使わない場合、自作関数や自作ps1ファイルを使うために一手間かかっていたけど、この手間をProfile.ps1ファイルにまとめて書けばいいので、自作処理がバッチファイルのように実行できるようになる

  • 自作関数を関数名で呼び出せるようにする

    自作関数の登録処理は以下のように書けばいい。Get-ChildItemコマンドレットで、myfunc_*.ps1ファイルを全部ゲットして、1つずつドットソースでps1ファイルを実行し関数を登録する。Profile.ps1ファイルはPowerShell実行時に自動で実行されるので、PowerShellが起動した時にはこれらの自作関数が関数名でコールできるようになっている 

    
            # 関数名でコールできるようにps1ファイル（myfunc_xx.ps1）をロードする
            Get-ChildItem $funcPath "myfunc*.ps1" | ForEach-Object { 
              . ($_.FullName) 
              Write-Debug ("load function : " + $_.Name)
            }
  • 自作ps1ファイルをスクリプト名で呼び出せるようにする

    自作ps1の登録処理は以下のように書けばいい。Get-ChildItemコマンドレットで、*.ps1ファイルを全部ゲットして、1つずつ拡張子を除くファイル名をエイリアスに設定する。Profile.ps1ファイルはPowerShell実行時に自動で実行されるので、PowerShellが起動した時にはこれらのps1はエイリアス名で実行できるようになっている 

    
            # スクリプトファイル名で実行できるようにエイリアス名をセットする
            $scriptFiles = Get-ChildItem -Path $scriptPath -Filter "*.ps1"
            foreach ($scriptFile in $scriptFiles) {
              # ファイル名から拡張子を除いた部分を取り出し、エイリアス名にする
              $aliasName = [System.IO.Path]::GetFileNameWithoutExtension($scriptFile.Name)
              # エイリアスを設定
              Set-Alias $aliasName "$($scriptFile.FullName)"
              Write-Debug ("set script Alias : " + $aliasName)
            }

Profile.ps1の実装フロー例

家のPCか会社のPCかを判別して自作関数フォルダのパス、自作ps1ファイルのフォルダパスを変数に代入し、LoadMyProgram()関数をコール。LoadMyProgram()関数で自作関数フォルダのパスにあるファイルをドットソースで実行し、自作ps1ファイルのフォルダパスにあるファイルのエイリアス名を登録する。これでPowerShellが起動した時には関数名やスクリプト名で自作プログラムが実行できるようになっている
