例外

例外は、プログラム実行中に発生する想定しないエラー（起こるかも知れないという想定はある）。また、throw文で意図的に例外を起こすこともできる

例外にはいろいろな型がある。こういう時、自分は全部を理解したいという気持ちになるのですが、この考えはあんまり良くない。発生したケース毎にそれだけケアした方がいいです。そうしないと例外を調べるだけで膨大な時間がかかってしまう（と思います）。

例外型の例

  • System.Exception

    これが例外の一番親のクラス。例外を型毎にcatchする場合、これを最後にする（そうしないと全部これがcatchするから）

  • System.Management.Automation.ItemNotFoundException

    ファイルやフォルダが存在しない場合の例外の型

  • System.UnauthorizedAccessException

    アクセス権がないオブジェクトへアクセスした場合の例外型

発生した例外の型を調べる方法。catchの中で「$_.Exception.GetType().FullName」を見る


        try {
            #このエラーは例外を発生させないので「-ErrorAction Stop」で例外に昇格させる
            Get-Content "C:\存在しないファイル.txt" -ErrorAction Stop
        }
        catch {
            #発生した例外の型を表示させる
            #Exceptionクラスの型を表示させる
            Write-Host $_.Exception.GetType().FullName
        }

        #この実行結果は以下となる（これがこの例外型）
        System.Management.Automation.ItemNotFoundException

.NETの例外型、PowerShellの例外型

PowerShellは.NET上で動いているので、例外の型も.NETの例外型を使っている。しかし、.NETの例外型をラップしてPowerShellの例外型にしているものもあり複雑

例えば、ファイルやフォルダが存在しない場合の例外型は以下のようになっている

  • .NETの例外型： [System.IO.FileNotFoundException]

    ファイルやフォルダが存在しない場合の例外の型

  • PowerShellの例外型： [System.Management.Automation.ItemNotFoundException]

    ファイルやフォルダが存在しない場合の例外の型

  • 存在しないファイルへのアクセスに対して発生する例外型がどちらなのかを見切れるか

    難しいと思う。このため、try/catchで型を指定したcatchブロックは、明確なケース以外は使わない方がいいかも 

    
            try {
              Get-Content "hoge.txt" -ErrorAction Stop
            }
            catch [System.IO.FileNotFoundException] {
              #この例では、ここには入らない
              #ファイルが存在しないという例外は一緒だが、この例外型は.NETの例外型のため
              Write-Host "例外：ファイルが見つからない（.NET）"
            }
            catch [System.Management.Automation.ItemNotFoundException] {
              #この例では、ここには入る
              #これはファイルが存在しないという例外のPowershellの例外型だから
              Write-Host "例外：ファイルが見つからない（PowerShell）"
            }

    存在しないファイルへのアクセスについて、.NETの例外型が[System.IO.FileNotFoundException]、PowerShellの例外型が[System.Management.Automation.ItemNotFoundException]なので、これが分かっていたら以下のように「,（カンマ）」でつなげて書くこともできる 

    
            catch [System.IO.FileNotFoundException],[System.Management.Automation.ItemNotFoundException] {
              ...
            }
