PowerShellの引数（実は奥が深い）

PowerShellの引数指定のいろいろ

引数を$args自動変数で受け取る方法

この方法は、使うメリットがないのであまり使われていない（なのでさらっと流す）。
この方法は、$argsという自動変数で配列として引数を受け取る。配列なので順番に意味がありどのインデックスの要素が何の引数かを渡す側と受け取る側がちゃんと認識していないといけない。
また、$argsには名前引数は格納されない。つまり、Param()で定義している引数は$argsには格納されない。


        #
        # Hoge.ps1
        #
        Param(
          [String]$myName = "Neko"
        )

        Write-Host ("myName = ", $myName)
        $i = 0
        foreach($arg in $args) {
          Write-Host '$args[', $i, '] = ', $arg, "`t", ", ", $arg.GetType()
          $i++
        }

        #実行結果（コマンドライン引数無しで実行）
        PS> .\Hoge.ps1
          myName = Neko   ← $myNameのデフォルト値が使われている

        #実行結果（コマンドライン引数を適当に渡してみる）
        #Param()で指定していない引数も配列で受け取っていることが分かる
        PS> .\hoge.ps1 -Fuga ISBE -myName Usagi
          myName =  Usagi                             ← 名前引数 $myNameで指定した値
          $args[ 0 ] =  -Fuga      ,  System.String   ← $Args[0]。-Fugaと「ハイフン」で引数名ぽく見えるが「-Fuga」自体が値
          $args[ 1 ] =  ISBE       ,  System.String   ← $Args[1]

また、Param()で指定した引数以上を渡した場合も、$Argsが受け取る！


        Param(
          [String]$myName,
          [String]$myAddress
        )

        Write-Host ("myName = ", $myName)
        Write-Host ("myAddress = ", $myAddress)

        if ($Args.Count -ge 1) {
          Write-Host $Args.Count
          $i = 0
          foreach($arg in $args) {
            Write-Host ("Args[", $i, "] = ", $arg)
            $i++
          }
        }
        
        # 実行結果（Param()で指定した以上の引数を渡してみた結果）
        PS> .\Hoge3.ps1 -myName Neko -myAddress KOBE Usagi Tori
        myName =  Neko      ← Param()で指定している名前引数
        myAddress =  KOBE   ← 〃
        2                   ← $Args.Countは 2 なので、2個の別の引数も受け取っている
        Args[ 0 ] =  Usagi  ← Param()で指定していない引数
        Args[ 1 ] =  Tori   ← 〃

引数をParam()ブロックで受け取る方法

Powershellでは、この方法がメジャー（と思うし、自分はこっちで書いている）。これは、関数やスクリプトの先頭に Param()ブロックを書き、その中で引数を指定する方法。

  1. 属性をつけて必須引数、位置引数、型指定などを表現できる（属性は角かっこ[] で指定する） 
    
            Param(
              [Parameter(Mandatory=$true, Position=0)][String]$myPath,  ← 属性は角かっこ[]で示す、また複数指定できる
              [Parameter(Position=1)][Int]$myCount=5,
              [Parameter(Position=2)][ValidateSet("L","M","H")][String]$Pri="M",
              [Switch]$Force
            )
            Write-Host ("myPath = ", $myPath)
            Write-Host ("myCount= ", $myCount)
            Write-Host ("Pri    = ", $Pri)
            Write-Host ("Force  = ", $Force)

            # 実行結果
              PS> .\Hoge.ps1 -myPath C:\Temp  ← 第1引数はMandatoryなので指定しないといけない
              myPath =  C:\Temp   ← 必須引数
              myCount=  5         ← オプション引数、デフォルト値が使われている
              Pri    =  M         ← オプション引数、デフォルト値が使われている
              Force  =  False     ← オプション引数、スイッチ引数は指定しない場合、False

            # この引数指定の意味
              $myPath   必須引数。指定しなければPowerShellから入力を促される。Positionが0なので第1引数。String型
              $myCount  オプション引数、Positionが1なので第2引数。Int型で、デフォルト値がある引数
              $Pri      オプション引数、Positionが2なので第3引数。String型で、取りうる値が「L、M、H」のいずれか。デフォルト値あり
                        ※ ValidateRange(1,10) のように数値範囲 1～10 を指定することもできる
              $foreach  オプション引数、スイッチ引数
    • [ValidateSet]

      [ValidateSet]は、選択できる範囲を指定する属性。[Parameter(Position=2)][ValidateSet("L","M","H")][String]$Pri="M" は、"L","M","H"の中から選択可能となる。

    • [ValidateRange]

      [ValidateRange]は、数値型で選択範囲を指定する属性。例えば、[ValidateRange(1,10)] は、1～10の数値が制定できる範囲となる。

  2. デフォルト値がある引数（デフォルト引数）の使い方は注意が必要

    先ほどの例で、$MyCount=5、$Pri="M" という引数は、それぞれ数値の5、文字列のMというデフォルト値を持っている。この例では型が違うからどちらの引数が省略されているかPowerShellは判断できるので問題はない。
    しかし、以下の例のように同じ型のデフォルト引数が複数ある場合、どちらの引数が省略されたかを判断できない
    以下の例は、2つのInt型デフォルト引数 $myAgeと$myValue を持つスクリプトの実行例を書いている。この例では「.\Hoge.ps1 35」として実行している。2つの引数に対して1つしか指定していないので、$myAgeか$myValueのどちらかは省略されている。実行結果を見るとPowerShellは、$myValueが省略されたと解釈して$myValueにデフォルト値が適用されている。
    しかし、ユーザ意図は$myAgeを省略して、$myValueに35 を指定したかった可能性がある。でも同じ型なのでどちらの引数が省略されたのか判断できない。という問題をはらんでいる。

    
            Param(
              [Parameter(Position=0)][Int]$myAge=25,
              [Parameter(Position=1)][Int]$myValue=75
            )  
            Write-Host("myAge  = ", $myAge)
            Write-Host("myValue= ", $myValue)            

            #実行結果
            PS> .\Hoge3.ps1 35  ← Int型のデフォルト引数 $myAge、$myValue のどちらかは省略されている。
              myAge  =  35    ← PowerShellは、コマンドラインから渡されたのは「$myAge」と判断しているが、
              myValue=  75       ユーザの意図は、$myAgeを省略し $myValueに対して 35 という値を指定している可能性がある！

    こういう時は、明示的に名前で引数を指定するように運用を気をつけないといけない（運用面）。また、コード側では、必須引数はPositionをつけるけど、デフォルト引数はPositionをつけないようにする（コード面）。 

    
            #実行結果
            PS> .\Hoge3.ps1 -myValue 35  ← $myAgeは省略し、$myValueだけ値を指定
              myAge  =  25    ← $myAgeはデフォルト値が使われている
              myValue=  35    ← $myValueはユーザ指定した値が使われている
  3. Param()内の順番が引数の順番

    Positionで位置を指定しない場合、Param()内の順番が引数順番とみなされるみたい。だけど、位置を指定しない引数を指定する場合は、名前で指定した方が安全。

    
            Param(
              [String]$myName,
              [String]$myAddress
            )  
            Write-Host("myName  = ", $myName)
            Write-Host("myAddress= ", $myAddress)

            # 実行結果
            .\Hoge3.ps1 neko usagi
            myName  =  neko     ← 位置指定していないが第1引数として受け取っている
            myAddress=  usagi   ← 同様

            # 実行結果（名前を明示して指定した方がいい）
            .\Hoge3.ps1 -myName neko -myAddress usagi
            myName  =  neko     ← 結果は同じだけど
            myAddress=  usagi
  4. 名前を指定する引数のメリット

    名前を指定すると引数の順番は気にしなくていいようになる

    
            # 実行結果（引数の順番を変えて指定できている）
            .\Hoge3.ps1 -myAddress usagi -myName neko
            myName  =  neko     ← 順番を変えて引数を渡しても名前で紐づけできている
            myAddress=  usagi
  5. Param()内には実行コードも書ける！

    通常、パスなどを引数で受け取るとそのパスを使う前にパスの存在をチェックして、存在しなければエラーにする等の処理を行うと思うが、それをParam()内で引数を受け取る時にチェックすることができる。
    それが、ValidateScript属性。つまり、Param()は単純な引数を受け取るブロックではないってことやな。

    ValidateScriptも属性なので、[ValidateScript({..処理..})] のように角かっこ[]の中に処理を書く

    
            [CmdletBinding()]
            Param(
              [Parameter(Mandatory=$true, Position=0)]
              [ValidateScript({
                write-host("ValidateScriptチェック中 : $_")
                If (-Not (Test-Path $_ -PathType Container)) {
                  throw "$_ が存在しません、中止します"
                } else {
                  $true
                }

              })]
              [String]$myPath
            )
            Write-Host("ここに来たという事はパスは正しい")
            
            # 実行結果
            PS> .\Hoge.ps1 C:\Hoge
            ValidateScriptチェック中 : C:\Hoge
            Hoge3.ps1: Cannot validate argument on parameter 'myPath'. C:\Hoge が存在しません、中止します

            # コード解説
            ValidateScriptは属性なので[]で囲む。処理はこの[]中に書く
            [Parameter()]、[ValidateScript]、[String] は引数 $myPath にかかる属性
            $_    : 渡された引数を示す
            throw : Catchブロックは無いが、この場合Powershellシステムが受け取る。これが無いとエラーで止まらない
  6. 属性の実体は、.NETのクラス

    VSCodeでコーディングをしているとインテリセンスが効いて、ValidateSc… と入力すると「ValidateScriptAttribute」が候補に出てくる。これはPowerShellの「ValidateScript」が、.NETの「ValidateScriptAttribute」の省略形だから。

    • [ValidateScript] ← .NETのValidateScriptAttribute の省略形
    • [ValidateSet] ← .NETのValidateSetAttribute の省略形
    • [Parameter] ← .NETのParameterAttribute の省略形

    なので、「ValidateScriptAttribute」を選択してもVSCode上では「ValidateScript」と表示される

  7. Mandatory=$true の場合はデフォルト引数は不可

    Mandatoryがtrueという事は必須引数という事。それに対してデフォルト値を指定すると省略できる引数とみなされるので不整合になる。

  8. 配列を引数に指定する

    配列を引数で渡すこともできる。

    
            Param(
                [String]$inu,
                [Array]$neko,               ← これが配列型の引数
                [String]$tori
            )
            Write-Host ("inu = ", $inu)
            Write-Host ("tori = ", $tori)
            if ($neko.Count -ge 1) {
              Write-Host $neko.Count
              $i = 0
              Write-Host ("neko = ", $neko)
            }

            # 実行結果（コマンドラインから引数で配列を渡す）
            PS> .\Hoge4.ps1 -inu Wan -neko Tama, Mike, Nya, Kuro -tori Pip    ← 配列（-neko）は、カンマで区切って要素を指定する
            inu =  Wan
            tori =  Pip
            4                             ← 配列要素が4つ
            neko =  Tama Mike Nya Kuro    ← 配列要素を表示している

    配列の型指定

    • [Array]

      この型は、Array型を示している。PowerShellの配列は型の混在が可能なので、Arrayで指定していたら、混合型の配列も受け取れる。

    • [Int[]]

      受け取る型がInt（Sysytem.Int32）であることが明白なら、[Int[]]でInt型の配列と指定してもわかりやすくていい。同様にString型だけの配列を受け取るなら、[String[]]でいい

    • [Object[]]

      オブジェクト型の配列を受け取る指定。PowerShellの配列は型の混在が可能なので、[Object[]]で指定していたら混在型の配列も受け取れる。[Array]と同様。

    [Int[]]で受け取る設定に対して、実際に渡されるものが数値以外があった場合

    • 型が違う配列が渡された場合

      [Int[]]に対して、引数が「1, 10, Neko, …」だった場合はエラーになる。PowerShellは、[Int[]]が指定れているので渡された引数が数値っぽい文字であってもInt型にキャストして受け取ろうとする。しかし、本当の文字が渡されてきたらキャストはできないので、エラーになる。要は、何が渡されるか、イレギュラーな引数が渡されたらどうするかなどを設計時にちゃんと考えておかないといけない。

  9. ポインタを引数で渡す

    コマンドライン引数では、ポインタを渡すことは無いと思うが、関数から関数をコールする場合、その引数にポインタを指定できる。

    ポインタを引数で渡す方法

    1. 関数側：
      • 引数は、[ref]引数名 で指定して受け取る
      • 値は、変数名.Value でアクセスする
    2. コール側：
      • 引数は、[ref]引数名を丸かっこで囲んで、つまり ([ref]引数名）で関数に渡す

    ポインタ渡しの関数コールは、関数側の仮引数は [Ref]$変数 で受ける。コール側の実引数は、丸かっこで囲んで ([Ref]$変数名) で渡す

    
            function test-ref {
              param (		
                [ref]$refArg,         ← [Ref]で修飾しているので、この仮引数はポインタ
                $noRef
              )		
              $refArg.Value += 10		  ← $refArg.Value でポインタ先のデータを示す
              $noRef += 20		
            }		
                
            $a = 1
            $b = 2
            test-ref ([ref]$a) $b     ← 関数コール。この実引数 ([Ref]$a) はポインタ渡し
            Write-Host '$a = ', $a
            Write-Host '$b = ', $b              

            # 実行結果
            PS> .\Hoge5.ps1
            $a =  11                  ← $aはポインタ渡ししているので、関数側で実体に対して+10されている
            $b =  2                   ← $bは、関数内で仮引数が+20されているだけなので、関数を抜けると無くなる
