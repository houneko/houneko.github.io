PS> 30

PS> 1020

PS> -9.9
* 乗算 PS> $result = 10.1 * 20.1
PS> 203.01000000000002
/ 除算 PS> $result = 10.1 / 20
PS> 0.505
% 剰余 PS> $result = 10 % 3
PS> 1

PowerShellの論理演算子

0以外の数値は、$trueとして扱われます。また「-b」で始まる論理演算子はバイナリでの論理演算となります

論理演算子
演算子 意味 サンプル例等
-and AND PS> $result = 10 -and 20
True
0以外の数値はtrueなので演算結果はtrueになる

PS> $result = $true -and $alse
False
-or OR PS> $result = $true -or $false -or $false
True
-xor XOR PS> $result = $true -xor $false -xor $false
True
PS> $result = $true -xor $false -xor $true
False
-not NOT PS> $result = -not(10 -and 20)
PS> False
-band ビット毎のAND PS> $result = 10 -band 3
2
バイナリでのAND、1010(b)と0011(b)のANDなので2となる
-bor ビット毎のOR PS> $result = 10 -bor 3
11
バイナリでのOR、1010(b)と0011(b)のORなので11となる
-bxor ビット毎のXOR PS> $result = 10 -xor 3
9
バイナリでのXOR、1010(b)と0011(b)のORなので9となる
-bnot ビット毎のNOT PS> $result = -bnot (10)
5
バイナリでのNOT、1010(b)の反転なので5となる		 

          #// 数値の場合、0以外は真。文字の場合は何かの文字があれば真となる
          > $val = -10      #// 負でも0以外なら真
          > $result = if($val) { '真です' } else { '偽です' }
          > $result
          真です
          #// バイナリの論理演算
          > $result = 10 -band 3
          #// 2進数で表示するメソッドやプロパティは無いので、Convertクラスのスタティックメソッドで表示する
          > [Convert]::ToString($result, 2).PadLeft(8, '0')  
          00000010

PowerShellの比較演算子

比較演算子は、数値の比較と文字の比較があります。文字の比較の場合、先頭に「-c」が付くと大文字小文字を区別する比較になる。また「-i」が付くと大文字小文字は区別しない比較になる。何もつかないものは「-i」と同じなので、覚えるのは「-c」が大文字小文字を区別した比較になるだけでいい

比較演算子の失敗例

PowerShellの比較演算子は、上で述べたように「-xxx」という形式になっています。これは他の言語とちょっと違う表現なので、最初は間違ってしまうこともあるかと思います。以下のはそのような失敗例です

正規表現を使った比較もあります。VBAのように正規表現のインスタンスを生成する必要はなく、いきなり正規表現の比較ができます


          if ($myVar = "On") {    #// このコードの意図は、$myVarが"On"だったらというものだが、
            ....                  #// この書き方だと、$myVarに"On"が代入され比較はされない。
          }                       #// $myVarによらずブロック内に入るので意図した動作にならない
比較演算子
演算子 意味 サンプル例等
-eq（-ceq、-ieq） 等しい
-ne（-cne、-ine） 等しくない
-gt（-cgt、-igt） より大きい
-ge（-cge、-ige） 以上
-lt（-clt、-ilt） より小さい
-le（-cle、-ile） 以下
-like（-clike、-ilike） ワイルドカードによる比較。一致するとTrueが返ってくる
-notlike（-cnotlike、-inotlike） ワイルドカードによる比較。一致しなかったらTrueが返ってくる
-match（-cmatch、-imatch） 正規表現による比較。一致するとTrueが返ってくる
-notmatch（-cnotmatch、-inotmatch） 正規表現による比較。一致しなかったらTrueが返ってくる 

          #// -like演算子の例
          > $myStr = "Neko to Usagi desu"
          > $result = if ($myStr -like '*Usagi*') { 'Yes' } else { 'No' }
          > Yes      #// ← -like演算子でワイルドカード比較した結果
          #// -match演算子の例
          > $result = if ($myStr -match '.+Usagi.+') { 'Yes' } else { 'No' }
          > Yes      #// ← -match演算子で正規表現を使った比較結果

PowerShellの書式演算子

PowerShellの演算子には文字列の書式を指定する「書式演算子」があります

書式演算子は、文字列に {0}、{1} のようなインデクスを埋め込んで、-f演算子（これが書式演算子）に続けて変数や定数などを指定します

Cのprintfに少し似ている感じだけど、ちょっと違うか（printf("円周率 = %.2f\n", pi);）

  • 書式演算子 基本パタン 
    
            > "{0} と {1} です" -f 5, 10           #インデクス{0}に5、インデクス{1}に10が対応している
            5 と 10 です
            > "{0} と {1} です" -f "Neko", "INU"   #インデクス{0}にNeko、インデクス{1}にINUが対応している
            Neko と INU です
  • 書式演算子 右寄せ、左寄せ

    右寄せは、インデクスに「カンマ」で数値を指定。左寄せはインデクスに「カンマ」でマイナス数値を指定する

    
            > "{0,4} と {1,-4} です" -f 5, 10
                5 と 10   です# ←5は、右寄せされて表示。10は左寄せで表示されている
  • 書式演算子 0パディング

    例えばループカウンタを表示させる時など、この0パディングを使うことがあります。ループは1から1000とかに桁数が増えるので表示がガタつくため0パディングして、0001、0002・・とすると見た目がきれいで見やすいです 

    
            > "{0:000}" -f 2     # 0を桁数分指定する方法
            002
            > "{0:d3}" -f 2      # d(10進数)、数値で桁数を指定する方法（どちらも同じ結果を得られる）
            002
  • 書式演算子 小数点表示

    0.00や#.##で小数点表示する。この時、桁数指定に対してデータの桁数が多い場合は指定桁数に合うよう小数点を四捨五入される

    
            > "{0:0.00}" -f 1.234
            1.23                                # 小数点以下2桁に四捨五入して、1.23になっている
            > "{0:#.##}" -f 10.245
            10.25
  • 書式演算子 金額

    N指定した場合、3桁ごとに「カンマ」が付いて金額の表示ができる。また、#,### のように指定することもできる（こっちの方が直観的でわかりやすいかも）。

    Nで指定した場合、小数点2桁も付いて表示されますが、N0としたら小数点表示をしないようにできます。N数字で小数点以下の桁数を指定できます

    
            > "{0:N}" -f 123456789         # 3桁毎にカンマで区切って表示。小数点以下は2桁表示がつく
            123,456,789.00
            > "{0:N0}" -f 123456789        # 3桁毎にカンマで区切って表示。N0なので小数点以下表示なし
            123,456,789
            > "{0:N3}" -f 123456789        # 3桁毎にカンマで区切って表示。小数点以下は3桁指定
            123,456,789.000
            > "{0:#,###}" -f 123456789     # #,### で3桁区切りを指定
            123,456,789
  • 書式演算子 %表示

    0%または、#%で指定するとパーセント表示することができます

    
            > "{0:#.#%}" -f 0.345
            34.5%
            > "{0:0.0%}" -f 0.345
  • 書式演算子 日付表示 
    
            > "{0:yyyy/MM/dd HH:mm:ss}" -f (Get-Date)  # Get-Dateは()かっこで囲む
            2020/03/20 12:10:51
  • 書式演算子 基数変換

    基数変換は、10進数と16進数しかサポートしていません。2進数や8進数は自分で計算しないといけないです

    
            > "0x{0:x4}" -f 100    # 10進数の100を16進表示
            0x0064
            > "{0:d}" -f 0x64      # 16進数の0x64を10進数表示
            100

PowerShellの配列演算子

配列演算子は、「配列要素に〇〇が含まれるか」の演算結果を返すものです

この書式は方向が逆で2種類あります（つまり左辺に配列を書くものと、左辺に値を書くものがあります）

-containsは「配列に値が含まれるか」の見方をする演算子です

-inは「値が配列に含まれるか」の見方をする演算子です


          # -contains、-inの書式
          <配列> -contains <値>     #// ← -contains演算子は左辺の配列に右辺の値が含まれるかを調べる
          <値> -in <配列>           #// ← -in演算子は左辺の値が右辺の配列が含まれるかを調べる
配列演算子
演算子 意味
-contains 左辺の配列に右辺の値が含まれるかを調べる。含まれていた場合は$trueが返る
-notcontains 左辺の配列に右辺の値が含まれないかを調べる。含まれていなかった場合は$trueが返る
-in 左辺の値が右辺の配列に含まれるかを調べる。含まれていた場合は$trueが返る
-notin 左辺の値が右辺の配列に含まれないかを調べる。含まれていなかった場合は$trueが返る 

          > $animals = @("neko", "inu", "usagi")
          > $animals -contains "hito"
          False
          > "hito" -in $animals
          False

PowerShellの型演算子

-is、-isnot型演算子は、オブジェクトが指定された型かを調べる演算子。$trueまたは$falseが返る

自分的には、オブジェクトが持っているGetType()メソッドで型は分かるので、あんまり使わないかな。。

-as型変換演算子は、オブジェクトを指定した型へ変換を試みる演算子です。型変換が失敗しても例外にならず$nullになる

そのオブジェクト自体が変換されるのではないという点に注意。変換した結果を代入する変数が必要です

配列演算子
演算子 意味
-is 書式：<オブジェクト> -is <[型]>。オブジェクトが指定した型であれば$true
-isnot 書式：<オブジェクト> -isnot <[型]>。オブジェクトが指定した型でなければ$true
-as 書式：<オブジェクト> -as <[型]>。オブジェクトを指定した型に変換を試みる 

          #// -is演算子
          > $animals -is [array]
          True
          > $animals.GetType() 
          IsPublic IsSerial Name          BaseType
          -------- -------- ----          --------
          True     True     Object[]      System.Array
          #// -as演算子
          > $strDate = "2000/10/20"
          > $strDate.GetType()                 #// String型
          > $strDate -as [Datetime]            #// datetime型へ変換を試みる
          > $strDate.GetType()                 #// String型のまま。この結果を代入する変数が必要
          > $myDate = $strDate -as [Datetime]  #// 変換結果を代入
          > $myDate.GetType()                  #// Datetime型
          IsPublic IsSerial Name          BaseType
          -------- -------- ----          --------
          True     True     DateTime      System.ValueType

PowerShellの三項演算子

三項演算子を使えばif文が簡潔に書くことができます。C言語にもあった演算子ですがあんまり使ってなかったです。PowerShellでは使うようにしようかな。。

三項演算子

三項演算子 書式：<条件>? <trueケース>: <falseケース> 

          > (Test-IsAdministrator)? "管理者権限です": "管理者権限はありません"
          管理者権限です

PowerShellのサブ式演算子

サブ式書式は、$(...) という書き方のものです。

PowerShellの変数は、ダブルクォーテーションの中に書くと展開されるようになっています。しかし、展開されないケースも存在しています。その場合、サブ式演算子（Subexpression Operator：$()式）を使います

サブ式演算子が無くてもいいケース


          #// サブ式演算子が無くてもいいケース
          > $myName = "Neko"
          > Write-Host "Hello, $myName"
          Hello, Neko                       #// この場合は、$()式を使わなくてもいい

サブ式演算子が必要なケース


          #// サブ式演算子が必要なケース１（プロパティやメソッドを参照する場合）
          > $myDate = Get-Date
          > Write-Host "今日は、$myDate.Day 日です"
          #// PowerShellは、$myDateまでしか変数と認識していない。このため、Dayプロパティは解釈されない
          今日は、07/12/2010 06:04:11.Day 日です    #// Dayプロパティが解釈されていない
          ↓
          > Write-Host "今日は、$($myDate.Day) 日です"
          今日は、12 日です    #// Dayプロパティが理解された

          #// サブ式演算子が必要なケース２（計算式を使う場合）
          > $a = 10
          $gt; $b = 20
          $gt; "sum = ($a + $b)"
          sum = (10 + 20)         #// $a + $b を計算してくれていない
          $gt; "sum = $($a + $b)"
          sum = 30                #// $()式を使うとうまくいく

          #// サブ式演算子が必要なケース３（コマンドレット結果を使う場合）
          > "Now is (Get-Date)"
          Now is Get-Date               #// Get-Dateコマンドレットが評価されていない
          > "Now is $(Get-Date)"
          Now is 07/12/2010 10:25:16    #// Get-Dateコマンドレットが評価されている

PowerShellの「.」ドットソース演算子

ドットソース（Dot Sourcing）は「.（ドット）とスペース」で指定する演算子で、ドットソース演算子の後に実行したいコマンドやファイル名を書きます

ドットソースで実行するとそのセッション、スコープ内でそのファイル内の変数や関数が実行できるようになります

これはモジュール化 と似ていますが、モジュール化よりも簡易的に部品を共有する仕組みと言えるかと思います

ドットソース演算子
演算子 意味
ドット演算子 書式：. スペース <式|ファイル|コマンド>

以下のSample.ps1を通常実行した場合と、ドットソースで実行した場合の違いを見てみます

通常の実行例


          #// Sample.ps1 を通常実行する
          function Say-Message {
            Write-Host $message
          }
          $message = "Hello"
          Say-Message

          > .\Sample.ps1     #// 普通に Sample.ps1 を実行
          Hello                 
          > $message         #// $message変数をタイプしても何も表示されない

ドットソースで実行した例

ドットソースで実行すると、このセッション内、スコープ内でスクリプトの変数や関数が利用できるようになる。このため、ドットソース実行後も$message変数が参照できています


          > . .\Sample.ps1     #// 最初の「. （ドット とスペース）」がドットソース演算子
          Hello                   
          > $message           #// $message変数を見ることができている
          Hello                   #// この「Hello」は変数内容を表示しているもの

ドットソースが良く使われる用途は（自分が使っている用途）、関数ライブラリの読み込みかなと思います。自分が使っている方法は、「自作関数を関数名で呼び出せるようにする」というものです。これは$Profile内で自作関数「hogeFunction.ps1」ファイルをドットソースで実行し、PowerShell起動時にその関数を実行できるようにしています 


          #// MyUtility.ps1
          function Get-Today { Get-Date }
          function Say-Hello { Write-Host "Hello" }
          function ...

          #// ドットソースで「MyUtility.ps1」を実行する（これでこのセッション内で関数が呼び出せるようになる）
          . .\MyUtility.ps1

          #// ドットソース実行後は以下のように関数が使えるようになる
          Get-Today
          Say-Hello
          ...

ドットソースの注意点

以下のサンプルコードは、Main.ps1内でSample.ps1をドットソースで実行していますが、両方のファイルで同じ変数名$messageを使っており名前がぶつかっています。この時、$messageは上書きされてしまいます 


          #// Sample.ps1
          $message = "Sample Message"

          #// Main.ps1
          $message = "Main Message"
          . .\Sample.ps1                  #// Main.ps1内で、Sample.ps1をドットソースで実行
          Write-Host $message

          #// Main.ps1を実行すると
          > .\Main.ps1
          Sample Message                  #// ドットソースで実行したファイルの$message変数内容になっている

なぜこうなるか？

ドットソースで実行したファイルは、その内容がそこに展開されるのと同じで、Sample.ps1の$message変数がここに展開されているからです


          #// Main.ps1
          $message = "Main Message"
          . .\Sample.ps1                  #// Main.ps1内で、Sample.ps1をドットソースで実行

            ↓

          #// これは以下のように書いたのと同じ
          #// Main.ps1
          $message = "Main Message"
          $message = "Sample Message"     #// Sample.ps1のドットソース実行は、その内容をここに展開したのと同じ

ということで、最初ドットソース実行はあまりイメージしにくかったのですが、自分の用途は$Profileで自作関数をコマンドのように呼び出せるようする使い方だけです

PowerShellの呼び出し演算子

呼び出し演算子（Call Operator）は、「&」でコマンドやスクリプト、スクリプトブロックを実行するための演算子です

この演算子は、スクリプトブロックを実行する時に真価を発揮するっぽい。スクリプトブロックという処理をデータとして扱いPowerShellらしい書き方ができます（自分は使いこなせてないので別途更新）

見た感じスクリプトブロックを無名関数のように処理のかたまりとして実行させることができます


          > $myCmd = "Get-Date"  #// 変数にコマンドを代入
          > $myCmd               #// 変数名だけ書くと...
          Get-Date                  #// Get-Dateという文字が表示されるだけ
          > & $myCmd             #// 呼び出し演算子（callOperator）を使った場合
          2010年12月04日            #// 文字列"Get-Date" がコマンドとして実行されている

スクリプトやスクリプトブロックを実行させる


          #// スクリプトを呼び出し演算子で実行する
          & .\Sample.ps1
          Sample.ps1スクリプト内容が実行される

          #// スクリプトブロックを呼び出し演算子で実行する
          $scriptBlock = {
            "Hello Block"
          }
          & $scriptBlock
          Hello Block               #// スクリプトブロックの内容が表示されている

引数をつけて実行することもできます


          #// 引数を指定して実行する
          #// スペースを含むパスの場合は、ダブルクォーテーションで囲む
          & "C:\Program Files\App.exe" -para -para2

          #// コマンドレットも引数付きで実行できる
          & Get-ChildItem -Directory

呼び出し演算子とドットソースの違い

  • 呼び出し演算子&（callOperator）

    呼び出し演算子&（callOperator）は、子スコープで実行される（別スコープ）。そしてその変数や関数は呼び出し元に残らない

  • ドットソース演算子

    ドットソース演算子は、同じスコープで実行され、その変数や関数は呼びだし元に残る

PowerShellの「,」カンマ演算子

「,」カンマ演算子は、配列を作るための演算子です

カンマ演算子
演算子 意味
カンマ演算子 書式：要素1, 要素2, 要素3, … 

          > $myArray = 10, 20, 30
          > $myArray.GetType()
          IsPublic IsSerial Name       BaseType
          -------- -------- ----       --------
          True     True     Object[]   System.Array   #//配列になっている

          #// これは、以下の書き方とほぼ同じ
          $myArray = @(10, 20, 30)

1つだけ要素を持つ配列を作る時の書き方


          > $myArray = ,10     #//要素が10だけの配列
          > $myArray = @(10)   #//これと同じ
          #// 配列を要素とする配列
          > $myArray = 100, 200, 300
          $gt; $myB = ,$myArray   #// [[100,200,300]] という配列になっている

PowerShellの「..」レンジ演算子

「..」レンジ演算子は、前後に開始の値と最後の値を指定し、その間は連続となるような指定をする演算子です。この演算子も配列を作ります

連続性がある文字にも使えます

レンジ演算子
演算子 意味
レンジ演算子 書式：開始の値..最後の値 

          > $myArray = 10..15
          > $myArray.GetType()
          IsPublic IsSerial Name       BaseType
          -------- -------- ----       --------
          True     True     Object[]   System.Array   #//配列になっている
          > $myArray
          10
          11
          12
          13
          14
          15

          #// 連続する文字にも使える
          > $myArray = 'a'..'e'
          > $myArray
          a
          b
          c
          d
          e

PowerShellのNull合体演算子「??」

null〇〇という演算子は3つあります。いずれも$nullに関する操作を行う演算子で普通にif文や三項演算子で書くよりも短く、簡潔に書けます（逆に言うと、if文や三項演算子で書けるので必須ではないとも考えられると思います）

名前が「Null合体演算子」というイメージしにくいものですが、?? という演算子で表現します。意味は左辺が$nullだったら、右辺の値を代入するというものです


          $name = $null
          $result = $name ?? "NewName"
          $result                       #// $resultは、NewNameと表示される
          #// ??演算子（Null合体演算子）は、以下の文と同じ
          #// if文で書く場合
          $result = if($null -eq $name) {
            "NewName"
          } else {
            $name
          }
          #// 三項演算子で書く場合
          $result = ($null -eq $name)? "NewName": $name

PowerShellのNull合体代入演算子「??=」

Null合体代入演算子、??=は、その変数が$nullなら値を代入するというものです


          $name ??= "NewName"

PowerShellのNull条件演算子「?.」

オブジェクトがnullかもしれない場合に、そのプロパティに対して操作する演算子


          $user = $null
          $user.Name にアクセスするとエラーになる

          #// $userが$nullかもしれない場合は、Null条件演算子を使うとエラーにならない
          $user?.Name     #// エラーにならず、$nullが返る
