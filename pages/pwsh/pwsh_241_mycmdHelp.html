Get-Helpで自作スクリプト、関数のヘルプ表示

自作スクリプトのヘルプをGet-Helpで表示させる方法

以前は、自作のスクリプトや関数のヘルプ表示を行う場合、-Helpオプションを作ってそれが指定されたら、ヒアドキュメントで使用方法などを表示していました（イメージで言うと、Cmd時代の自作コマンドの/hオプションでヘルプ表示みたいな感じ）。

一方、標準のコマンドレットは「Get-Help コマンドレット」でヘルプ表示するので同じ形式でしたいなと思っていました

実はこれができるというのが分かり、それをまとめたものがこの章です

適切なコメントブロックに所定の書式でヘルプ情報を書いておけば、他のコマンドレットと同様に「Get-Help 自作スクリプト」「Get-Help 自作関数」でヘルプ表示されます

  • Comment-based Help

    <#～#>のコメントブロックの中にヘルプ表示する内容を書く

  • 各キーワードで指定する

    ヘルプ項目毎のキーワードがあり、キーワード毎にヘルプ内容を書く

    
            <#
              .キーワードA
                ......
              .キーワードB
                ......
            >#
  • 先頭に書く

    スクリプトの先頭、関数の先頭（function宣言の前、またはfunctionブロック内の先頭）に書く。[Cmdletbinding()]も先頭に書くルールですが、Comment-based Help の方が先に書きます。Get-Helpは先頭にあるコメントブロックからヘルプ情報を取るので先頭に無いとだめという事です。また、あくまでコメント文なので[Cmdletbinding()]の書き位置とも競合しません

  • 各キーワードについて

    各キーワードの意味です。また書く順番もこの通りにするのが良いです（暗黙的にこの順番になっているらしい）

    No キーワード名 意味 例
    01 .SYNOPSIS 概要を1行で要約したもの ファイルをバックアップするスクリプトです
    02 .DESCRIPTION 詳細説明を書く、複数行になってもいい 指定されたフォルダのファイルをバックアップフォルダにコピーします
    既存ファイルがある場合は上書きされます
    03 .PARAMETER A1 コマンドライン引数のA1について書く。各パラメータ毎に分けて書く A1：[String]型で、フォルダパスを指定します
    04 .EXAMPLE 使用例を数パタン書く My-BackUp -targetPath D:\MyBackup
    My-BackUp -Debug
    05 .INPUTS パイプライン入力の型を書く（コマンドライン引数は .PARAMETER） System.String
    06 .OUTPUTS スクリプトや関数が返すもの System.Boolean スクリプトの成功・失敗
    07 .NOTES 補足情報や改版履歴など PG: HOUNEKO
    Version: v1.00.12
    08 .LINK 関連リンク情報、関連コマンドなど https://....

ヘルプは単にコメントブロック内容を表示しているのではない

Get-Helpで自作スクリプトのヘルプ表示をする場合は、上述の通り先頭に<#～#>で所定のキーワードでヘルプ内容を書けばいいです。が、単に記述しているヘルプメッセージが表示されるわけでないっぽいです

どういう事かというと、例えば「.PARAMETER」は、実際にそのスクリプト内にパラメータが宣言されていないと表示されません。つまり、Get-Helpは単に定義された文字列を表示するだけではなく、対象物をパースしてヘルプ内容を表示しています 


        <#
        .SYNOPSIS
        ............
        .DESCRIPTION
        ............
        .PARAMETER targetPath
        検索対象のフォルダ。省略した場合は "C:\Temp"
        .PARAMETER fileTypes
        対象の拡張子。複数指定する場合はカンマ区切りでも可
        例: *.csv,*.txt,*.log
        省略時は *.csv
        .PARAMETER Recurse
        サブフォルダも含めて検索する場合は指定
        .PARAMETER fileOut
        結果をCSV形式で出力する場合は指定
        .PARAMETER ThrottleLimit
        並列処理時の同時実行数（PowerShell 7以上）。省略時はCPUコア数
        .PARAMETER help
        古いIF用のヘルプスイッチ
        #>

        [Cmdletbinding()]
        param(
                              # 実際のパラメタが定義されていないとヘルプ内容は表示されない
        )

        表示結果）
        #### param()が未定義の場合のGet-Help結果（PARAMETER部分だけ抜粋）   
        #### ← 各パラメタが表示されていない
        PARAMETERS
            <CommonParameters>

古いIFも残しておく（任意）

PowerShellのコマンドレットやスクリプトのオプションは「-名前 値」で指定するようになっているので、Cmdからやっていたユーザの中には、「-Help」があるだろうと想定しているケースもあるかと思います。

そのため「-Help」も用意しておくと親切かなと思います。

その時、Get-Helpと同じものを出してもいいし、ヒアドキュメントで作ったストリングを表示してもいいかなと思います。

  1. Get-Helpと同じ内容を表示させる場合 
    
            param(
              ...
              [switch]$help
            )

            # 古いユーザ向け help スイッチ対応
            if($help){
              Get-Help $MyInvocation.MyCommand.Path -Full
              return
            }
  2. Cmd時代っぽいヘルプ表示にする場合 
    
            param(
              ...
              [switch]$help
            )

            # ヘルプ表示する内容のヒアドキュメント
            $myUsage = @'
            $myName /  $myVersion
              指定されたフォルダ配下のHTMLファイルを調べる
              使い方:
                My-CheckHoge [-path <ディレクトリ名>][-tags <a,b,c...>][-Help][-Debug]
                Input :   -path     : [String]HTMLファイルがあるディレクトリ名
                          -tags     : [Array]チェック対象のタグ名を配列で指定する。例： a, img, link, script
                          -help     : [Switch]スイッチパラメータ。使用方法を表示する
                          -debug    : [Switch]スイッチパラメータ。Debug用
            '@

            # 古いユーザ向け help スイッチ対応
            if($help){
              Write-Host $myUsage -ForegroundColor DarkYellow
              Return
            }
