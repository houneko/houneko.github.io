PowerShellの実行前に必要な知識

PowerShellのプログラム（シェルスクリプト、*.ps1）は作ってもすぐに実行できないようになっています。PowerShellは結構何でもできるので、PCの起動や実行に影響を与えるコードを作ることもできてしまいます。このため、実行するためにはいろいろなガードがかかっているのかなと思っています。はぁ、そうですか。で、そのガードが実行ポリシーってものです。

キーワードは、実行ポリシーと管理者権限です。これらは別々の言葉ですが、実行制御には実行ポリシーがかかわっており、実行ポリシーの変更には管理者権限が必要という関係です

実行ポリシーとは

PowerShellのスクリプト（*.ps1ファイル）は、バッチファイルのようなものですがバッチファイルのように、ダブルクリックしても実行できないようになっています。なんでかというと、悪意のあるスクリプトの不用意な実行を防ぐためかなと思います。
ダブルクリックせずにシェルから実行しようとしても同じで、「xx.ps1：このシステムではスクリプトの実行が無効となっているため・・・」のようなメッセージが出て実行できません。このように、スクリプトの実行を制御しているのが実行ポリシーというものです。

で、デフォルトの実行ポリシーは「Restricted」になっているので、ユーザが作ったスクリプト（*.ps1）は実行できなというわけです。

じゃ、実行ポリシーを変えたらいいやんけとなりますが、今度はこの実行ポリシーを変えるには管理者権限が必要ということです。いろいろガードがかかっているっていうのはこういう意味です。

また、この実行ポリシーの概念があるので、部内にps1ファイルを公開する場合にもう一段階気を付けないといけない。つまり、バッチファイルのように単純に渡すだけではだめってことです。
ps1ファイルを単純に渡してもユーザ先の実行ポリシーはRestrictedになっている為、実行できないし「実行ポリシーを変えて」と言ってもできない人がいるので、ps1ファイルの配布方法は考えないといけない

実行ポリシーの確認方法

PowerShellには、実行ポリシーを確認するためのコマンドレットがあり、それを使えば簡単に確認することができます。それが「Get-ExecutionPolicy」コマンドレットです


        > Get-ExecutionPolicy
        RemoteSigned    # 今の実行ポリシーが「RemoteSigned」であることがわかる

        # -Listオプションをつけたらスコープ毎の実行ポリシーがわかる
        > Get-ExecutionPolicy
          Scope          ExecutionPolicy
          -----          ---------------
          MachinePolicy  Undefined
          UserPolicy     Undefined
          Process        Undefined
          CurrentUser    Undefined
          LocalMachine   RemoteSigned

実行ポリシーのスコープ

実行ポリシーには、ポリシーを適用する範囲が分けて管理されており、以下のスコープがあります（自分が使ってきた中ではあんまり気にしなくてもいい感じだけど）

スコープの種類
スコープのタイプ 意味・スコープ範囲
MachinePolicy グループポリシーでこのコンピュータの全ユーザが対象となるスコープ。グループポリシーで強制
UserPolicy グループポリシーでこのコンピュータの現在のユーザが対象となるスコープ。グループポリシーで強制
Process 現在のユーザの現在のセッションが対象となるスコープ
CurrentUser 現在のユーザが対象のスコープ
LocalMachine このコンピュータの全ユーザが対象のスコープ

実行ポリシーを変更する

実行ポリシーを変えれば、自作の*.ps1を実行できることが分かりましたが、実行ポリシーを変えるには通常ユーザ権限ではできません。なので、PowerShellを管理者権限で起動して実行ポリシーを変更できる権限にしてから操作すればできます。
自分で作ったps1ファイルを実行できるようにしたい場合は、実行ポリシーを「RemoteSigned」に変えればいい です

実行ポリシーの変更は、「Set-ExecutionPolicy」で行うので、引数に「RemoteSigned」を指定してあげればいいです。しかし、以下のようなエラーになって変更ができません。 


        Set-ExecutionPolicy: Access to the path 'C:\Program Files\PowerShell\7\powershell.config.json' is denied.
        To change the execution policy for the default (LocalMachine) scope, start PowerShell with the "Run as 
        administrator" option. 
        To change the execution policy for the current user, run "Set-ExecutionPolicy -Scope CurrentUser".

このエラーの原因は、管理者権限が無いので実行ポリシーを変更できなかった というものです。

PowerShellで作ったps1ファイルを実行するには、実行ポリシーの変更が必要で、実行ポリシーを変えるには管理者権限が必要ってことです。
このようなガードはバッチファイルにはかかっていないので、PowerShellの方が安全管理が厳重になっています

  • 管理者権限での起動

    Win+R → WT → Ctrl+Shift+Return 、と起動すれば管理者権限で Windows Terminal が起動するので、管理者権限になってからもう一度「Set-ExecutionPolicy RemoteSigned」を行えば実行ポリシーを変えることができます

    実行ポリシーの変更は、スコープを指定しない場合は「LocalMachine」スコープが指定されたことになり「LocalMachine」スコープに対して、RemoteSigned がセットされます

    
            PS> Set-ExecutionPolicy RemoteSigned   # 管理者権限なので、エラーが出ずに変更できた
            PS> Get-ExecutionPolicy
            RemoteSigned                              # 実行ポリシーが変更できた
  • 管理者権限であるかの確認方法

    以下のコマンドを実行すれば、管理者権限で起動しているのかどうかわかる

    
            ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole("Administrators")

ps1ファイルの配布について

自分で作ったps1ファイルをユーザに配布する場合、実行ポリシーがあるためユーザ先で実行できない可能性があります（つまり、実行ポリシーの概念を知らない人やその変更ができない人もいる）。このため、一工夫がいります。

配布先の人にその人のPCの実行ポリシーを変更してもらうように依頼すべきか？

これはやめた方がいい。実行ポリシーの概念を理解していない人もいるし、そもそもセキュリティの観点で実行ポリシーがかかっているので変更するのは望ましくない

じゃ、どうすんの？以下の方法３でやればいい（方法１と２は不可）

  • 方法１）スコープを限定して実行ポリシーを「RemoteSigned」に変更してもらう 
    
            PS> Set-ExecutionPolicy  RemoteSigned  -Scope  Process
            # -Scopeオプションでスコープを「Process」に指定しているので、現在のセッションだけ実行ポリシーを
            # RemoteSignedに変えることができる

    これで、このセッション中は実行ポリシーをRemoteSignedに変わる。これはセッションが終われば元の実行ポリシーに戻るのでセキュリティ的に安全。だけど、これは一時的であるがユーザに実行ポリシーを変えてもらう事なので、実行ポリシーを理解していないユーザには難しい。
    このためこの案は不可

  • 方法２）バッチファイルで、Processスコープの実行ポリシーを変えるようにする 
    
            hoge.batファイルの内容
            PowerShell -Command "Set-ExecutionPolicy RemoteSigned -Scope Process"
            # Processスコープで今のセッションだけ、実行ポリシーをRemoteSignedにする。
            # バッチファイルを終了すると元の実行ポリシーに戻る

    このバッチファイルは、Processスコープでこのセッションに限り実行ポリシーをRemoteSignedにしているが、バッチファイルには何も処理が無いので、バッチ終了後に元の実行ポリシーに戻る
    このためこの案も不可

  • 方法３）バッチファイルで、Processスコープの実行ポリシーを変え、さらにps1ファイルを実行させる 
    
            hoge.batファイルの内容
            PowerShell -NoProfile -ExecutionPolicy RemoteSigned -File "test.ps1"

            # -ExecutionPolicyオプションでRemoteSignedにして「test.ps1」ファイルを実行する
            # バッチファイルを終了すると元の実行ポリシーに戻るが、test.ps1は実行されている
            # これでユーザは、実行ポリシーを意識せず「test.ps1」スクリプトを実行できる

    この方法は、バッチファイル内に実行ポリシーを指定して、対象のps1ファイルを実行しているので、初心者でもps1ファイルの実行方法を意識せずに行える

よって、実運用では上記の方法３をベースのバッチファイルと実行本体のps1ファイルのセットで配布し、ユーザでの実行はバッチファイルでやるようにすればいい。バッチファイルはGUI環境ではダブルクリックでも実行できるのでコマンドラインに慣れていないユーザにも使える
