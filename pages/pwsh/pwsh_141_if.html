PowerShellのif文

PowerShellにもif文があります（当然...）。基本的な構造や構文は他の言語と同様ですが、$nullとの比較は少し注意が必要です


          # if文の基本形
          if (条件式１) {
            条件式１がtrueの時に実行される処理
            ...
          } elseif (条件式２) {
            条件式２がtrueの時に実行される処理
            ...
          } elseif (条件式..) {
            条件式..がtrueの時に実行される処理
            ...
          } else {
            全ての条件式がFalseの場合に実行される処理
            ...
          }

$nullとの比較での注意事項

$nullと配列を比較する場合、少しだけ注意が必要です。通常、if文の条件式は（$変数名 -eq 値）のように「左辺が変数」「右辺が比較する値」という形で書きますが、$nullと配列の比較の場合は「左辺が比較する値（つまり$null）」と書きます


        #// 普通のif文
        if ($myName -eq 'Neko') {     #// 左辺は「$myName変数」、右辺が比較する値
          ....
        } else {
          ....
        }

なぜ、$nullと配列変数の比較の場合は「左辺に$null」を書くのか？

これは、そう推奨されているからです。本当の理由は意図しない比較になる可能性があるからです


        $nameAry = @($null, "Neko", "Usagi")    #// $nameAryは、存在するが$nullを含んでいる配列
        $wk = "Hoge"
        $wk = $nameAry -eq $null                #// $wkに 何が返ってくるか見てみる
        if ($nameAry -eq $null) {               #// この条件式は $null となるので False側に分岐する
          Write-Host "Yes"
        }
        else {
          Write-Host "No"                       #// よって、これが表示される
        }

デバッグ画面

「$nameAry -eq $null」は、$nameAry配列の$nullに一致した要素が返ってくる（つまりインデクス0の$nullが返ってくる）。このため、配列がnullなのかではなく、配列に$nullが含まれるかの意味になってしまう。

だから、配列と$nullの比較は、$nullを左辺に書く。こう書くと左辺がスカラー値なので、$trueか$falseのどちらかが返ってくるので「配列そのものが$null？」の判別ができる

参考）C言語でのNULL値の比較

Cの時もNULLとの比較は、左辺にNULLを書きますが、これは少し意味が違います

これは、NULLを代入するコーディングミスをコンパイル時に見つけ出させるテクニック（比較==を間違って、代入にしても左辺がNULLならコンパイル時にエラーとなって分かる）

※でも最近のコーディングスタイルはこの書き方は特に推奨していないようです。コンパイラが強力になっており、変数が左辺で値が右辺という書き方がより自然なためです（まぁ、昔の人はNULLを左に書くのが慣習になっているかも。そういうコードを見たら歴史的な背景があったんだなと思えばいいでしょう） 


          if (NULL==p) {    //左辺が変数だと間違って、p=NULLにしてしまってもコンパイルは通るので気づかない
            ....            //左辺がスカラー値だと、NULL=p はエラーになって分かる
          }
