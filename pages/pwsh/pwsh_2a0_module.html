PowerShellのモジュール化

モジュール化とは

モジュール化とは、複数の関数や変数などを再利用できるように部品化することだと言えると思います。モジュール化しない場合、あるスクリプトa.ps1で行った処理を別のb.ps1でも行いたい場合は、その処理や関数をコピーして使うような形でしたが、この処理（関数）をモジュール化しておけば、インポートするだけで関数を呼び出せるようになります

最初にPowerShellをやり始めた時に部品化して再利用できたらいいのにな。と思ったことがありましたが、当時はモジュール化を知らなかったのでコピペでやっていました

モジュール化する関数は「psm1ファイル」に書きます。「psd1ファイル」は必須ではないですがマニフェストファイルというもので、このファイルにpsm1ファイルの情報を書きます

この*.psm1ファイルに複数の関数を記述し、それらの関数を外部公開設定にすることでその関数が再利用できます

また、モジュール毎にフォルダを作成し、その中にpsmd1ファイル/psmd1ファイルを格納します。この時モジュール名とフォルダ名は同じにする慣習があります （こうしないと動かないというわけでないですが、わかりやすいです）


          #例：「my.System.Security」 というモジュールを作成した場合
          ..\My.System.Security              ← My.System.Securityモジュール用のフォルダ
              ├ My.System.Security.psm1     ← モジュールファイル（同名になっている）
              └ My.System.Security.psd1     ← マニフェストファイル

モジュール化の仕組み、構成

モジュール化は、モジュールファイル「*.psm1」とマニフェストファイル「*.psd1」それと、モジュールを使うスクリプトファイル「*.ps1」で構成されています。

  • psm1ファイル

    このファイルがモジュールファイル。このファイルの中に部品化したい関数を書く。これらの関数のうち公開したいものをエクスポートすれば外部から参照できるようになる

  • psd1ファイル

    このファイルはマニフェストファイル。このファイルにはpsm1ファイルに関する情報を書く。マニフェストファイルは無くてもいい

  • 任意のps1スクリプトファイル

    公開関数を使う側のファイル。インポートすることでpsm1ファイルの中の関数を部品として使えるようになる

モジュールの格納フォルダ

モジュール化する関数はpsm1ファイルに書き、その情報はpsd1ファイルに書くということが分かりましたが、この章では、これらのファイルはどのフォルダに格納するかを説明します

といっても答えは「どこでもいい。だけど特定のフォルダに格納すれば自動ロードされる」となると思います

例えば、自作モジュールをMyModulesというフォルダの下に作るでもいいし、所定のフォルダの下に作るでもいいという事です。どっちがいいかは一概には言えないので、自分の環境にあわせて方針を決めたらいいと思います

  1. 所定のフォルダにモジュールファイルを格納

    所定のフォルダとは何？

    この所定のフォルダを定義している「PSModulePath」という環境変数があります（注：$がついてない点に注意。つまりPowerShellの自動変数ではない）。環境変数なので$env:で内容を確認できます

    自分の場合複数のパスが表示されたのですが「C:\Program Files\PowerShell\Modules」の下でいいです

    
              # pwshで確認する場合
              $env:PSModulePath -split ';'
              # cmdで確認する場合
              echo %PSModulePath%

              # 複数のフォルダがモジュールパスとして定義されている
              C:\Users\xxx\OneDrive\ドキュメント\PowerShell\Modules
              C:\Program Files\PowerShell\Modules
              c:\program files\powershell\7\Modules
              C:\Program Files\WindowsPowerShell\Modules
              C:\WINDOWS\system32\WindowsPowerShell\v1.0\Modules

    自動ロードとは？

    この所定フォルダの下に自作モジュールフォルダを作れば、インポートしなくてもモジュールファイルで公開している関数が呼び出せるという事です。その関数が使われる時にこのPSModulePathを探してロードしてくれます 

    
              #例：「my.System.Security」 というモジュールをPSModulePathを配下に配置する
              C:\Program Files\PowerShell\Modules   ← PSModulePath
                ├ My.System.Security.psm1          ← モジュールファイル（同名になっている）
                │   function f1 {...}     ← この関数はインポートしなくても自動ロードされる
                │   function f2 {...}
                │   ...
                └ My.System.Security.psd1

    2. じゃ、PSModulePathに自作のモジュールを置けばいいやとなりかけたのですが、自分の環境で言うとこのパスはつかっていません。なんで？については以下を見てください

  2. 自分のフォルダにモジュールファイルを格納

    当初、PSModulePathに追加しようと思っていましたが、自作のモジュールが分かるようにした方がいいかと思い「C:\My\MyCmd\MyModules」というフォルダに置くことを考えました

    そうすると、以下のようなことが起きます

    
              # PSModulePathに無いので個別にフルパス指定しないといけない
              Import-Module "C:\My\MyCmd\MyModules\NekoModule"

              # 以下のようにすれば、自分のモジュールパスを PSModulePathに追加できるけど
              # この追加はこのセッションでしか有効ではない。
              # また、セッションが終了するとパスの追加は無くなってしまう
              $env:PSModulePath += "C:\My\MyCmd\MyModules\NekoModule"

    じゃ、どうする？

    プロファイルに書いておけば、都度追加しなくてもいいしセッションが終わっても設定は残っている

    
              # $Profileに以下のように記述しておく
              $env:PSModulePath += "C:\My\MyCmd\MyModules\Utility"
              $env:PSModulePath += "C:\My\MyCmd\MyModules\File"
              $env:PSModulePath += "C:\My\MyCmd\MyModules\System"
              ・・・

    これでめでたしめでたしとなりかけたのですが、開発したスクリプトファイルは部内に公開することがあり、問題が出てきました

    問題点「PSModulePathだとユーザ環境のPSModulePathにもモジュールを追加しないといけない」という問題がおきます。つまり自作パスを作ってもPSModulePathに含めるとユーザ環境をいじらないとインポートできないようになってしまいます

    自分だけが使う場合や一定のスキルを持っているチームで使う場合は、どの方法でも大丈夫だと思いますが、一般ユーザにスクリプトファイルとモジュールファイルを配布する方法は検討が必要となります
