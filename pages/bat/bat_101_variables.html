batファイルの変数

batファイルの変数の基本事項

  • 変数のスコープと寿命

    バッチファイルの変数のスコープはそのCmdプロセスで、バッチファイルが終了すると変数も消滅します

    callで別のバッチファイルから呼び出された場合、同じCmdプロセス内となるので名前衝突しないように注意がいります

  • 変数の設定

    何らかのプログラムであれば変数はあると思いますがbatファイルにも変数という概念があります。batファイルの変数の設定は「set」コマンドで行います。
    しかしこの変数の設定は他の言語に比べて特殊なので間違いやすいと思います。0から始める場合はそういうもんなんやと覚えたらいいですけど、他の言語の知識があると「はぁ？」となるかと思います。なので注意が必要です

    1. スペースを含めたらだめ

      batファイルの世界は、スペースが区切り文字となっているのでスペースに意味があります。このため変数の宣言でもスペースを含めてしまうと違う意味になってしまいます

      以下の例は、変数名と＝の間にスペースがあり、また＝と値の間にもスペースがあるため、だめな例です

      
rem 「myVar」という変数に「Neko」を代入したい意図だけどこの指定はだめ
set myVar = Neko
echo %myVar%      ← 何も表示されない
echo %myVar %     ← 表示される。「myVar 」後ろのスペースを含めて変数名が宣言されたことになってる

      これが何でだめかというと「myVar」という変数を宣言した意図に対して作成される変数は「myVar 」という変数名になる（myVarの後ろに半角スペースを含めた変数名）

      また代入される値も同様に「Neko」を意図しているのに「 Neko」が代入される

    2. ダブルクォーテーションで囲む

      変数の宣言と代入

      普通の言語で""で囲むと文字列になるけどbatの世界では文字列リテラルは無い。このためbatの世界では「""」で囲んでも文字列ではないです

      この例の場合、setに"myVar=Neko"が渡されると、「""」を取って、=の左が変数名と解釈されて、=の右が値と解釈されて代入されます

      
rem 変数の宣言と代入は「""」で囲むようにする
set "myVar=Neko"

      "myVar=Neko"とするのは、スペースが含まれている場合の誤動作を防ぐための運用なので、例のようにスペースが無い事が明白であれば、普通に「set myVar=Neko」でも動作は同じです。

      だけど、実運用では全部「""」で囲むようにした方がいいです。「""」ありで宣言しているものや、無しで宣言しているものが混在すると間違いやすいし統一していた方が見やすくていいはずです

  • 変数の参照方法

    変数の参照方法も癖があり、変数名そのままでは参照できません。

    batファイルの変数の参照は、変数名の前後に「%」をつけて参照します

    
set "myVar=Neko desu"
echo myVar        ←このechoは、myVar変数に「%」がついていないので変数名と認識されない
echo %myVar%

rem 実行結果
myVar             ← 変数名と解釈されていないので「myVar」というデータとして表示されている
Neko desu         ← %myVar%で指定したので、変数内容が表示されている
