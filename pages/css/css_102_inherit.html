CSSの継承プロパティと非継承プロパティ

htmlは、要素（開始タグから終了タグまでの一連のかたまり）は入れ子の構造となっている。CSSの設定をする場合、どこにCSSスタイルを適用するかを考えていくが、この時親要素に設定したCSSが子に継承されるものとされないものがあるという話です。
ここの理解があやふやだと意図したデザインにならなくて何で？と悩むことになるので、自分的には重要と思っていています

継承プロパティ、非継承プロパティ

継承プロパティ

継承プロパティは親要素が、あるプロパティに値を設定している時、子要素以降の要素がそのプロパティに値を指定していなければ、親要素が指定した値を継承するプロパティ。


  HTML側
  <body>
    <p>あなたは<b>猫</b>ですか？</p>
  </body>
  

  body {
    color: red;
  }

cssで設定されているのは、bodyセレクタのみ。bodyの子要素であるp要素や、pの子要素のb要素（body親から見ると孫要素）は文字色の指定はしていないが、親要素body の文字色指定が、継承されており赤字になっている。つまり、colorプロパティは継承プロパティってこと。

親要素がcolorプロパティを指定すると子要素や孫要素が自分でそのプロパティを設定していなければ、親要素の設定が継承される。

非継承プロパティ

非継承プロパティは親要素が、あるプロパティに値を設定している時、子要素以降の要素がそのプロパティに値を指定していなければ、そのプロパティが持っている初期値が使われるというもの。


  HTML側
  <body>
    <p>あなたは<b>猫</b>ですか？</p>
    <p>わたしは<b>猫ではない</b>です。うさぎです。</p>
  </body>
  

  body {
    color: red;
    border: solid;
  }

cssでbodyセレクタに設定されているのは、colorプロパティと borderプロパティ。子、孫要素の p要素や b要素は何も指定していない。
colorプロパティは、継承プロパティなので、p要素やb要素にも継承されている（赤字になっている）。一方、borderプロパティは非継承プロパティなので、p要素やb要素には継承されておらず、枠線が表示されているのはbody部分だけ。この時、p要素やb要素のborderプロパティは初期値「none」が設定されていることになる。なので、border枠線はbody要素にしか表示されていない。

非継承プロパティを継承させることも可能。非継承プロパティを子要素や孫要素に継承させたい場合は、「inherit値」で明示的に指定することができる。


    p { border: inherit; }
    b { border: inherit; }

非継承プロパティのborderを、p要素やb要素に継承させている。これにより、body要素についていた枠線が、p要素やb要素にも表示されていることがわかる。

継承プロパティ、非継承プロパティのルール

継承プロパティのルール

「文字・文章に関するもの」は基本的に継承される

よく考えると、日常世界でも文字や文章は親も子も同じ書式や同じフォントなどにするのが一般的な気がします。それを考えるとこのような整理になっているのはある意味納得

文字や文章に関するプロパティは、color、font-***、line-height、text-align・・・などがある

非継承プロパティのルール

「箱、レイアウト、見た目の形に関するもの」は基本的に継承されない

これもよく考えると、子の見た目は必ずしも親の見た目と同じにしないといけない事はない。子は子で自由なレイアウトにする方が自由度が高いように思う。なので、日常世界と同じような考えでの継承・非継承の整理に近いのかなと思う

非継承プロパティは、width、minなどのサイズ系、marginやpaddinなどの見た目系、borderやbackground-**などの見た目系、displayやflexなどの見た目系・・などがある

継承プロパティ、非継承プロパティの失敗例

失敗事象

CSSだけでアニメーションができるのですが、そのサンプルを作っている時に間違った例です

まず現象ですが、以下のHTMLとCSSがあった場合、アニメーションはするが画像サイズが意図したサイズにならなかったという問題が起きました


      <div class="my-animation">
        <img src="**.png" alt="" />     <!-- このpngをアニメーションさせる意図 -->
      </div>
      

      .my-animation {
        width: 20%;                     /* 非継承プロパティなのでdivにしか効いてない */
        animation-name: fadeInOpacity;
        animation-duration: 5s;
      }

      @keyframes fadeInOpacity {
        from { opacity: 0.35; }
        to { opacity: 1; }
      }

width:20%で、画像のサイズを20%にする意図だったけどwidhtは非継承プロパティなので、このクラスがかかっている親divにしか効いてない。つまり、親divは幅が20%（ビューポートの20%幅）になっているが、子の画像には効いてない

修正内容

修正は「my-animation」の子孫「img」に対するデザインを追加しそこでサイズを指定するように修正

このような「親でレイアウト、子でサイズ調整」というような設定は良く行われる。


      .my-animation {
        width: 20%;                     /* 非継承プロパティなのでdivにしか効いてない */
        animation-name: fadeInOpacity;
        animation-duration: 5s;
      }
      /* このCSS設定を追加 */
      .my-animation img {
        width:100%;                     /* 親divが縮んでいるので親divに対して100%指定する */
        height:auto
      }
      @keyframes fadeInOpacity {
        from { opacity: 0.35; }
        to { opacity: 1; }
      }

原因は、divにかかっている my-animationクラス内のプロパティは非継承プロパティなので、子のimgには影響を与えていないからということであった。

div.my-animation内のプロパティ 子imgへの影響 その他
width 影響しない だから画像のサイズが変わらなかった
animation-name 影響しない
animation-duration 影響しない
  1. 疑問１

    これで修正はできたけど、疑問が出てきました。

    widthは、divから子へは継承されないので、divの幅だけが20%になっている。これはわかる。で、imgはサイズ指定がないから元のサイズのままで表示されている。これもわかる。

    じゃ、なんでアニメーションは動いたの？？

    答え

    この例のアニメーションは、opacityの変化。opacityは特別で「継承はされない」けど見た目の変化はする。つまり、divだけがアニメーションしているが、opacityは親の描画結果が見た目imgにもかかり「親の見た目と一緒に変わる」ということ。

    だからimgもアニメーションしているように見えていた（opacityの変化だけ）

  2. 疑問２

    ということは、divには何も指定せず、imgの方にmy-animationをつけたらいいのでは？

    答え

    YESだが今のままの方がいい

    確かにimgがアニメーションの対象なので、こちらに全部設定をもってきてdivは何も指定しないことでも同じ結果は得られる。だけど、div親でレイアウト管理して、子でサイズ調整するやり方が将来の拡張をしやすいメリットがある。例えば、テキストもアニメーションしたい場合、div内にpタグを追加したらいい。html構造は変わらないので影響は少ない（CSSはテキストに対するアニメーションなどを指定しないといけないが）
