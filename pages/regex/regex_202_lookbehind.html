正規表現の後読み

正規表現の後読みには、肯定後読みと否定後読みがあります。また後読みも位置へのマッチ になります（マッチしても目に見えない）

後読みとは何か？

後読みとは、正規表現エンジンが対象を文字列を左から右にチェックしていった時、左側が既に見た文字で右側がこれから見る文字となりますが、後読みはこの左側（つまり過去）を今の位置から見てチェックするという意味。

逆に先読みは今の位置から右側（これから読むので未来の文字）だから、先読みと考えられる

このように理解したら先読み：右側（未来）、後読み：左側（過去）と覚えられる。後読みという言葉がしっくりこないけど、過去読みとかだったら自分はわかりやすい

後読みパタンも先読みパタンと同様に確認にだけ使われてマッチした文字には含まれない

肯定後読み（Positive lookbehind）

肯定後読みは、(?<=左側にある文字列) で指定するパタン。(?で始まる拡張グループ構文の1つ。
肯定後読みは、今の位置からパタンで示した文字が「左側に」あるかをチェックする

肯定先読みと否定先読みパタンの覚え方（自分バージョン）

肯定先読みと否定先読みはどちらも拡張グループ構文なので「(?」で始まる。この部分は共通。次に肯定先読みは「=」が続くが、否定先読みは「<が来てから=」

この時、<は「左側」をイメージしていると考えると覚えやすい（と思いませんか）

  • 肯定先読みのパタン指定：(?=右側の文字列）
  • 肯定後読みのパタン指定：(?<=左側の文字列）
  • 覚え方

    (?で始まり、「=があれば肯定」、「!があれば否定」

    (?で始まり、「<があれば後読み」、「<がなければ先読み」

実際に使う時は、位置だけだと使いにくいのでその位置にからめて何かの文字と組み合わせて使う


        #肯定後読み
        > "houneko" -match 'neko(?<=hou)'  # 左側に「hou」がある neko へのパタンマッチ
        False   ## ← このパタンマッチは False になっている！！

ん？ neko(?<=hou) のマッチング結果はFlaseになっている。なんで？？

後読みの注意点

「neko(?<=hou)」は、人間がそのまま解釈すると、nekoという文字パタン と 肯定後読みで左側に houという文字があるものと理解すると思います。なので論理的にはマッチするはずと考えてしまうと思いますが、この書き方だと意図したマッチになりません

何でか?


正規表現エンジンは対象の文字列を左から右に評価していってます。今、パタンがneko(?<=hou)だと最初にnekoにマッチするものを探していきnekoにマッチした後の位置から左側を見てhouがあるかを評価するとhouが無いのでマッチしないという事です

じゃ、どう書くの？

先に評価されるパタンを先に書く という事だと思います。この例だと先に出る文字はhouなので「(?<hou)」、その後に「neko」と書く。つまり「(?<hou)neko」と書けばいい

こう書くと先に「hou」がマッチする。これは肯定後読みとして定義されているので、この文字列が左にあるパタンと解釈されて、その次を見る。その次はnekoなので、houがあってnekoがあればパタンにマッチする。肯定後読みパタン部分はマッチした文字列には含まれないので、結果「neko」がマッチした結果となる


文字列：houneko

パタン：(?<hou)neko

nekoがマッチしている

否定後読み（Negative lookbehind）

否定後読みは、(?<!左側にある文字列) が無い事をチェックするパタン
否定後読みは、今の位置からパタンで示した文字が「左側に」ない かをチェックする


        > "nekousagi" -match '(?<!inu)usagi'  # 左に「inu」が無い「usagi」を探すパタン
        True
        > $Matches
        Name      Value
        -------------------
        0         usagi          # ← このusagiは後読み位置（左側）にinuが無い usagi にマッチしている
