クラスモジュールを使う

クラスモジュールとは

クラスモジュールは、標準モジュールと同様にVBAコードを書くところ（モジュール）で、挿入タグから標準モジュールではなくクラスモジュールを選択する。
Webページにはクラスモジュールを使えばオブジェクト指向になるというような説明があるけどこれは少し説明が不足していると思う、VBAはMicrosoftが作ったシートやセルのクラスをインスタンス化したシートオブジェクトやセルオブジェクトにプログラミングを行っているので、VBAはオブジェクト指向であると言える（と思います）。この環境に自分のクラスを作成し、よりオブジェクト指向のプログラミングができる（つまり、クラスモジュールを使わなくてもオブジェクト指向であるが、クラスを使う事でよりオブジェクト指向プログラミングができるってことだと思う）

クラスの特徴

  • クラスモジュールを挿入することでクラスができる（デフォルト名：class1というモジュールができる）
  • クラスモジュール内に「Sub」や「Function」プロシージャを書く
  • クラスモジュールでは、マクロの記録は使えない

    自分でプロパティやメソッドを定義していくから（元々マクロの記録は使ってないので関係ない）

  • クラスモジュールは1つで、1つのクラス定義

    つまり、1つのクラスモジュールの中に複数のクラスを定義できない

    VBAのクラスは、1つのクラスモジュールが1つのクラスなので、他の言語のようなクラス定義をして、プロパティやメソッドを書いていくのではなく、クラスモジュールに標準モジュールと同じようにSubプロシージャやFunctionプロシージャを書いていく（Class xxのような記述は書かなくてもいい）

    
            Option Explicit
            Private dvdName    As String        '// Dimで宣言しない
            Private dvdPrice   As String        '//

            Public Function GetDvdName() As String
              GetDvdName = dvdName
            End Function
  • クラスには、プロパティとメソッドがある

    当たり前やな。プロパティは値、メソッドが処理

  • 命名規則（慣習的なもので、明確なきまりは無い）
    クラスの命名規則
    項目 命名タイプ 備考 例
    クラス名 パスカルケース ハンガリアン記法はあんまり使わんらしいが「Cクラス名」にするか CMyClass
    メソッド名 パスカルケース PowerShellライクで動詞名詞の構成にする CalculateNumber
    コレクション名 パスカルケース 末尾に「s」をつけて複数形にする MyPages
    プロパティ名 キャメルケース myName
    プライベートメンバ名 キャメルケース 「m_」接頭語をつける m_localValueｘ
  • クラスモジュールの拡張子は「.cls」

    クラスモジュールをエクスポートするときの拡張子は「.cls」になる（標準モジュールは、.bas）

  • VBAのクラスは継承をサポートしていない

    ということは、例えば車クラスを定義して、別にスポーツカークラスを作ろうした場合、スポーツカークラスにも車クラスの機能を１から書く必要がある（車クラスを継承できないから）。クラスを使うメリットが半減してしまうなぁ

  • VBAのクラスは多様性もサポートしていない

    オブジェクト指向では「カプセル化」「継承」「多様性」というのが大きな要素である。この中の「継承」「多様性」をサポートしていないということなので、VBAのクラスはオブジェクト指向だけど限定的なということになりそう。つまり、高度なオブジェクト指向プログラミングはできないのかなと思います。

Public と Private

プロパティ、メソッドには、Public/Privateの設定があり、Public修飾したメンバだけがクラス外からも見えるようになる
