VBAのライブラリとは

VBA本体には含まれていないもので、外部から追加して利用できるライブラリ。外部ライブラリを使う事でVBAの機能を拡張したり使いやすくできる

事前バインドと実行時バインド

VBAで外部ライブラリを使う場合、外部ライブラリのバインド方法は「事前バインド」と「実行時バインド」の2つがある。

  • 方法1: 事前バインド（参照設定）

    事前バインドは、外部ライブラリを使う前に「参照設定」でバインドしておく方法。参照設定はVBEで「ツール」-「参照設定」で対象のオブジェクトにチェックを入れておけばいい（これが事前バインド、参照設定という方法）

    この方法のメリットとデメリットは以下の通り

    • メリット

      事前にバインドしているので、マクロ開発コーディング時に外部ライブラリの各メンバの候補が出る（自分の環境ではインテリセンスが効かなかったが・・）

    • デメリット

      デメリットは大きい。作成したマクロをユーザに提供する場合、ユーザ環境も事前に参照設定を行っておく必要がある。ITリテラシのばらつきがあるのでユーザによっては対応ができない可能性がある。そうするとVBAはインタプリタなので外部ライブラリ処理のところでエラーになる。 

    
              '//事前バインド（参照設定）していた場合の コード例
              Dim fso   As Object
              Set fso = New FileSystemObject  '事前バインド済なので、New「オブジェクト名」でインスタンス生成できる
  • 方法2: 実行時バインド

    この方法は、VBEの参照設定は触らずに、コード内で外部ライブラリをバインドする方法。この方法のメリットはマクロを実行するユーザ側では何も設定しなくてもいいという点

    
              '//実行時バインドの コード例
              Dim fso   As Object
              Set fso = CreateObject("Scripting.FileSystemObject")  'CreateObject()で外部ライブラリをバインドする

つまり、開発側からみると補完が効くので事前バインドしている方がいい。一方、ユーザ側からみると何か設定しないといけないのはいやとなる。じゃ、どうすればいいの？
実際のやり方は、開発側では参照設定を行い事前バインドするが、コードは実行時バインドの方法で書く。そうすると、開発側は補完のメリットを受けながらコード作成できるし、コード自体は実行時バインドで書くのでユーザ側からは何も設定せずにマクロを実行できるメリットがあってWin-Win
