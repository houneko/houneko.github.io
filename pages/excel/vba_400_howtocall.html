値を受け取らない場合のFunctionプロシージャコール

Functionの返す値を受け取らない事は可能

Functionプロシージャは、値を返す関数ですが、この値を受け取らないことも可能です。何か他の言語と混同していたのかずっと、FunctionプロシージャHogeをコールする場合は値を受け取らないといけないと思っていました。

つまり以下の例のようなコールができます


        '// Hoge()関数
        Function Hoge() As Boolean
            Debug.Print ("Enter Hoge()")
            Hoge = True
        End Function

        '// Hoge関数をコールするが値は受け取らない
        Sub MyTest()
            Hoge            '// 値を受け取らずにコールしている
        End Sub

これを知った時あぁそうですか。というだけの話だったのですが、同じようにしようとした時にエラーになりました。

以下はエラーになったサンプル例


        '// MyTestFunction()関数
        Function MyTestFunction(Optional ByVal fg As Boolean = False, Optional ByVal path As String ="") As Boolean
            ...
            MyTestFunction = True
        End Function

        '// MyTestFunction関数をコールするが値は受け取らない
        Sub MyTest()
            MyTestFunction(True, "mypath")      '// 値を受け取らずにコールしようとしたらエラー
        End Sub

これは何でかというと値を受け取らない場合は、()を付けてコールできないというルールがあるためです（このルールも意味わからん）

つまり、引数があるFunctionプロシージャを値を受け取らずにコールする場合、以下のどちらかの書き方にしないとだめです


        '// Functionプロシージャの値を受け取らない場合のコール方法
        MyTestFunction True, "myPath"
          または
        Call MyTestFunction(True, "myPath")

なんでこんな仕様なのかな。。

追加： この仕組みはSubプロシージャも同じでした。。Subプロシージャも値を返さないから、値を返さないFunctionプロシージャと同じコールの仕方になるのかな・・
