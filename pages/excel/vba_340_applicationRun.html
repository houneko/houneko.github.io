Application.Run による関数コール

Application.Run とは

Application.Runは、関数名を名前（文字列）で指定して、その関数をコールする方法。仕事で関数名を直接指定しない呼び出しのマクロを作る必要があり、Cの関数ポインタみたいな使い方ができないかとWebを調べている時に見つけた方法。

自分の感想としては、ブック間のマクロコールはそんなに必要性は感じない（複数のブックを維持しないといけないのが煩雑。それだったら、その処理を、このプロジェクトに別モジュールとして追加した方が管理しやすい）、だけどこの方法で関数の固有名を使わずにコールできるので、このコール部分を汎用的なコードにすることができる点はいいと思う

Application.runの書式、注意点など

  • 書式： Application.Run("マクロ名・関数名", 引数1, 引数2,…)
  • 注意点： 第一引数がコールされるマクロ名・関数名。これを「文字列」で指定する
  • 注意点： 他のブック内のマクロや関数をコールできるが、その場合は「ブック名!プロシージャ名」で指定する
  • 注意点： 引数には構造体は指定できない！最初知らずに何で？と悩んだ（早よ言え!）
  • 注意点： 引数はByValでしか渡せない（ByRefで渡せない）
  • 注意点： コールされる関数は、Publicで宣言しておく

Application.Runのサンプル例

同一モジュール内の関数も、別モジュールにある関数もPublicであれば別モジュールから見えるので、呼び出し方は同じ

別ブック（別プロジェクト）の関数をコールする場合 


        '/////////////////////////////////////////////////////////////////////
        '// Application.Runでコールされる関数
        '/////////////////////////////////////////////////////////////////////
        Function myApplicationRunFunc(myVal As String) As Boolean
            Debug.Print ("Enter myApplicationRunFunc()")
            Debug.Print ("myVal = " & myVal)
            myVal = "changed in myApplicationRunFunc()"
            Debug.Print ("Exit myApplicationRunFunc()")
            myApplicationRunFunc = True
        End Function


        '/////////////////////////////////////////////////////////////////////
        '// Main
        '/////////////////////////////////////////////////////////////////////
        Sub myMain()
            Dim showMsg         As String
            Dim funcName        As String
            
            showMsg = "Neko desu"
            funcName = "myApplicationRunFunc"

            '// Application.Runでコールする（同一モジュール内）
            If Not Application.Run(CStr(funcName), showMsg) Then Exit Sub
            Debug.Print ("after call : " & showMsg & " : Application.Run TEST OK!")

            '// Application.Runでコールする（別モジュール）
            funcName = "OuterModuleWithParameter"
            If Not Application.Run(CStr(funcName), showMsg) Then Exit Sub
        End Sub

        結果（イミディエイトウィンドウへの出力結果）
          Enter myApplicationRunFunc()  '// Application.Runでコールした関数に入った
          myVal = Neko desu             '// 渡された引数を表示
          Exit myApplicationRunFunc()   '// Application.Runでコールした関数からリターン
          after call : Neko desu : Application.Run TEST OK!   '// 引数は ByVal で渡すので関数側ので変更しても変わらない
          Exit Main

実務での実装イメージ

この業務では、ユーザに「資材結果ファイル」とオプションファイル（明細ファイル、発注データファイル、作業報告書ファイル）を指定してもらい「資材結果ファイル」内の情報、オプションファイルの情報を取得してレポートを作成する。
オプションファイルは指定されたり、場合によっては指定されないがある。また、オプションファイルに関する仕様は変動することが想定されている（オプションファイルを追加、または削除などがある）

このため、オプションファイルをコールする処理を汎用化したいという想いがあった（普通に固有関数名でコールする方法だと、仕様変更時に既存処理へif文を追加したりして、既存部分への影響がある。これを避けるために関数名を指定せずにコールする方法を検討したもの）

  1. ユーザにファイルを指定してもらう
    この例では、ユーザが指定したオプションファイルは「明細フォイル」と「作業報告書ファイル」。「発注データファイル」は指定なし
  2. ユーザ設定を辞書に登録しておく
    キーがオプションファイルに対する関数名、バリューが有効か無効を示すBool値
  3. 資材ブックを調査する関数内で、オプションファイルがあればApplication.Runをコールする（ディスパッチするラッパー関数をコール）

    以下の黄色の部分がディスパッチ用の関数をコールしている所（このディスパッチ関数内でApplication.Runをコールする）

  4. Application.Runでコールする

    オプションファイルが追加されたら、そのオプションファイル用に関数を新規に作成が必要だけど、コール部分は固有名でコールしていないので変更しなくていい（辞書は追加が必要）なので、仕様変更があっても新規関数を追加すれば動くコードになるはず。
